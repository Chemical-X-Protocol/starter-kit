# Chemical X: Truth and Cost Remediation

**Date:** 2026-10-06
**Status:** Awaiting review
**Scope:** `@chemx/starter-kit` CLI, audit rule engine, MCP gateway, task database

---

## 1. Problem Statement

Chemical X is sold on two promises: it conserves agent tokens, and it tells
agents the truth about a codebase. Measured against its own source, it
currently does neither reliably.

The tool is stable. All 17 commands execute without crashing; no stack traces,
no missing modules, no undefined calls. The nonzero exits from `audit`,
`verify`, and `lint` are gates failing correctly. This is not a stability
problem.

It is a truthfulness problem. The tool reports confident, specific, wrong
numbers, and charges a large token toll to report them.

### 1.1 Measured evidence

Collected 2026-10-06 against commit `72ce53b`, target `cli/` (228 files,
34,135 LOC).

| Observation | Measurement |
| :--- | :--- |
| `audit cli` verdict | 9/100, Grade F, 125 violations |
| `audit .` verdict | 0/100, Grade F, 142 violations |
| `verify` verdict, same repo | **A+, score 100, 0 violations** |
| `CONTROL_FLOW_INLINE_BOOLEAN` hits | 87 of 125 violations |
| `AI_SLOP_SHALLOW_CATCH` hits | 30 of 125 violations |
| Task DB entries | 530 total, 405 marked done |
| Task entries citing the two rules above | **366 of 530** |
| `audit --json` output | 115,407 bytes, approx 28,800 tokens |
| `team task list --json` output | 102,844 bytes, approx 25,700 tokens |
| Protocol docs loaded per session | 13,293 tokens across 5 files |
| `audit` human output that is ANSI art | 11,171 of 12,700 bytes (88%) |
| `chemx --help` | 14,206 bytes, approx 3,550 tokens |
| `read --outline` reduction | 98% to 99% (claim is 80%+) |
| `read --outline --enrich` reduction | 3% to 10% |
| `verify --json` on a green run | 220 bytes, approx 55 tokens (claim holds) |

### 1.2 The compounding defect

The two low-precision rules do not merely produce noise. `chemx audit`
auto-triages violations into assignable team tasks. 366 of 530 task entries
were generated by those two rules, and 405 entries are marked done.

The two rules fail in different directions, so the completed work carries
different risks:

- `AI_SLOP_SHALLOW_CATCH` is too aggressive. Roughly two thirds of sampled hits
  are intentional best-effort swallows (section 4.2). Tasks it generated may
  have added error handling that obscures deliberate behavior.
- `CONTROL_FLOW_INLINE_BOOLEAN` is too permissive (see the companion lexicon
  spec). Decomposing conditions into named booleans is the desired standard, so
  tasks it generated pointed in the right direction. The risk in that work is
  name quality: a mechanical decomposition produces restatement names such as
  `isChEqualsBackslash`, which satisfy the rule and teach nothing.

Independent of direction, auto-triage converted every violation into a task
row as a side effect of a read command, and the database also serves rows from
other projects. Agents are mandated to query that database first, so its noise
is paid for on every session.

### 1.3 Claims that hold

Stated for balance, and to protect them from regression:

- `read --outline` exceeds its advertised reduction: 98% to 99% against 80%+.
- `typecheck --json` is genuinely silent at 157 bytes.
- `test --json` on a green run is 220 bytes, consistent with the 45 token claim.
- `q --blast-radius` correctly resolves 14 affected files across 2 hops and
  names impacted tests.

## 2. Non-Goals

- No package split in this spec. The `chemx` / `chemx-studio` separation is
  real and agreed, but it is downstream work. Pass 2 draws the seam; promoting
  that seam into two published packages is a later spec.
- No feature removal. The web UI, navigator TUI, tesseract HUD, team swarm,
  and generator all stay.
- No framework or dependency changes.
- No retroactive revert of the 405 completed tasks. Pass 1 produces the
  evidence needed to decide that separately.

---

## 3. Acceptance Criteria

"Works 100%" is defined here as six testable conditions. Each is enforced by a
test that fails on regression, not by convention.

1. **Rule precision.** Every rule in `RULE_REGISTRY` has a fixture pair: source
   that must trigger it, and known-good source that must not. Zero false
   positives from `AI_SLOP_SHALLOW_CATCH` against the kit's own `cli/`.
   Control-flow rule precision is governed by the lexicon spec, criteria 2
   and 3.
2. **Gate coherence.** `verify` and `audit` cannot report different grades for
   the same scope. A test asserts equality across both entry points.
3. **Scope correctness.** The MCP gateway resolves `cwd` per call. The task
   database cannot serve rows belonging to another project.
4. **Cost ceilings.** `audit --json` under 1,500 tokens by default.
   `team task list` under 500 tokens by default. Protocol docs under 2,500
   tokens total. Each asserted by a byte-budget test.
5. **Claim accuracy.** Every number published in `README.md`, `llms.txt`, and
   `benchmarks/README.md` is produced by a test that fails when the claim
   drifts from measured reality.
6. **Self-clean.** `chemx verify` passes on chemx's own `cli/`, honestly
   scoped, with no rule above its recorded baseline (lexicon spec section 6).
   This is the finish line: the tool passes its own gate on its own code with
   no scope bug concealing the result.

## 4. Pass 1: Truth

Ordered first because every pass-1 defect causes wasted agent work today.

### 4.1 Control flow lexicon (moved)

**Superseded.** This section originally proposed exempting guard clauses,
same-subject class tests, and existence chains from
`CONTROL_FLOW_INLINE_BOOLEAN`, on the reasoning that those constructs are
idiomatic JavaScript.

That reasoning was wrong for this project. The standard is that the `if` never
asks a question: it reads a named answer. Under that standard those constructs
are violations, and the rule was not too aggressive but roughly twelve times too
permissive, detecting 87 of 1,867 actual violations.

The corrected design, measurements, three-layer predicate lexicon, autofix
tiers, and ratchet baseline are specified in
`2026-10-06-chemx-control-flow-lexicon-design.md`.

Three consequences land on this spec:

- Section 4.3's requirement that `--triage` become opt-in is now critical
  rather than merely correct. The lexicon rules report 1,867 violations on first
  run, and auto-triage would convert them into 1,867 task rows.
- Section 4.4's gate-coherence fix must land before any autofix pass runs,
  otherwise autofixed files are validated by a `verify` that is not auditing
  them.
- Section 4.4 must ship together with the lexicon spec's ratchet baseline
  (its section 6). Once `verify` audits `cli/` it reports the full existing
  debt, and without a ratchet the gate moves from a false A+ to a permanent F.
  Neither state carries information.

### 4.2 `AI_SLOP_SHALLOW_CATCH` precision and escape hatch

**Current logic** (`cli/audit/ai-slop-detector.js:167`) flags any catch whose
body `isShallowCatchBody`, at severity `HIGH`, with no opt-out.

Sampled hits divide roughly one third genuine, two thirds legitimate:

```js
} catch { /* Read-only filesystem in sandbox */ }   // intentional, correct
try { warmIndexDb(cwd); } catch {}                  // intentional cache warm
} catch { /* ignore JSON parse error */ }           // genuine defect
```

**Required behavior.**

- Introduce an explicit annotation: `// chemx-allow: best-effort <reason>`
  on or immediately above the catch clause exempts it. A reason string is
  mandatory, so the decision is documented and greppable rather than silenced.
- Lower the default severity from `HIGH` to `MEDIUM`. A swallowed error in an
  optional path is a smell, not a high-severity hazard.
- Escalate to `HIGH` only when the swallow occurs in a non-optional path:
  the `try` block assigns to a binding that is read later in the same scope
  without an intervening default. This is the case where swallowing produces
  silent `undefined` propagation, which is the real defect class the rule was
  written to catch.

### 4.3 Task database remediation

The DB currently holds 366 entries generated by the two rules above, plus rows
referencing at least four files that do not exist in this project
(`src/style.css`, `src/components/organisms/CardDetailModal.vue`,
`src/components/molecules/MobileScanningBar.vue`,
`src/components/organisms/splash-page/hero/SplashHeroPersonaSwitcher.vue`).

**Required behavior.**

- Add a `chemx team task prune` subcommand that re-runs each open task's
  originating rule against its target and deletes the task when that violation
  no longer reproduces. Open tasks from rules governed by the ratchet baseline
  (the control-flow rules) are deleted outright: the ratchet tracks that debt
  as a per-rule count, not as per-site tasks. Reports counts per reason.
- Tasks marked done are retained. Those originating from
  `AI_SLOP_SHALLOW_CATCH` are flagged `suspect_origin`, since that rule's
  false-positive rate means the work may have altered intentional behavior.
  Those originating from control-flow rules are not suspect in direction; their
  quality is assessed by `CONTROL_FLOW_RESTATEMENT_NAME` once the lexicon spec
  lands.
- Rows whose `target` path does not resolve under the current project root are
  reported, not silently dropped, so cross-project contamination is visible.
- Make `--triage` opt-in only. `chemx audit` currently auto-triages as a side
  effect of a read command; the observed run wrote 30 task rows during what the
  caller issued as an audit. A read command must not mutate state.

### 4.4 Gate coherence

**Current logic** (`cli/verify.js:258`):

```js
const resolveDefaultTargetDir = (cwd) => {
  if (fs.existsSync(path.join(cwd, 'src'))) return path.join(cwd, 'src');
  if (fs.existsSync(path.join(cwd, 'blueprints'))) return path.join(cwd, 'blueprints');
  return cwd;
};
```

`verify` audits `src/` when present. In this repo `src/` holds the web UI
source, not the CLI, so `verify` reports A+ on 200 UI files while the 228-file
tool is never audited. Any project with code outside `src/` (monorepo, `app/`,
`lib/`, `packages/`) receives the same false green.

**Required behavior.**

- `verify` and `audit` resolve scope through one shared function. Divergent
  defaults are the bug; a single resolver is the fix.
- Scope resolution prefers, in order: explicit `--dir`, a `chemx.scope` field
  in `.chemxrc`, then the project root.
- Drop the `src/` heuristic. Silently auditing a subdirectory and reporting a
  whole-project grade is the defect.
- When resolution is ambiguous (multiple plausible source roots, no config),
  `verify` refuses and names the candidates rather than guessing. A refusal is
  recoverable; a false A+ is not.

### 4.5 MCP per-call `cwd` resolution

**Current logic** (`cli/mcp/server.js:18`) captures `process.cwd()` once at
server start. Every handler then defaults to that value. Observed effect: a
relative read issued from this project resolved into
`/home/xopher/www/x/Xophz-COMPASS/apps/my-card-vault/`.

Absolute paths work. Relative paths silently target whatever directory the
server booted in. Because `action: 'write'` exists, this is a
file-creation-in-the-wrong-repository risk, not merely a failed read.

**Required behavior.**

- Accept an optional `projectRoot` parameter on the master `chemx` tool, and
  resolve all relative paths against it per call.
- When `projectRoot` is absent, resolve against the directory containing the
  nearest `.chemxrc` or `.chemx/` above the target path.
- Reject a resolved path that escapes the active project root, with an error
  naming both the requested and resolved paths. Silent cross-project
  resolution is never acceptable.

### 4.6 Project fingerprint on the database

`.chemx/` is gitignored, so the contaminated DB was carried in by a directory
copy rather than by version control.

**Required behavior.** Stamp the project root path and a content fingerprint
into the DB on creation. On open, a mismatch produces a refusal naming both
projects and offering reinitialization. Serving another project's rows silently
is the failure being prevented.

### 4.7 Destructive regeneration of hand-authored directives

Discovered 2026-10-06 by accident: running `chemx pillars --json`, which reads
as a request for the pillar configuration in machine-readable form, overwrote
both `AGENTS.md` (477 lines, 40,491 bytes) and `.cursorrules` with generated
template stubs of 30 and 8 lines. Recovered from git; nothing was lost because
both files were tracked.

**Current logic** (`cli/pillars-wizard.js:113`):

```js
if (!isDryRun) {
  fs.writeFileSync(agentsPath, agentsMdContent, 'utf-8');
  fs.writeFileSync(cursorRulesPath, cursorRulesContent, 'utf-8');
```

The write is gated only on `!isDryRun`. The `--json` flag affects output
formatting only. There is no backup, no diff, no confirmation, and no
`--force` gate. The destination files are not named on the command line, so a
caller has no signal that two root-level documents are the target.

This is the same defect class as section 4.3: a command that reads as an
inspection mutates state. Here the consequence is worse, because the overwritten
content is hand-authored prose that no amount of regeneration restores.

**Required behavior.**

- `pillars` writes `AGENTS.md` and `.cursorrules` only with an explicit
  `--write` flag. Default behavior reports what would change.
- Before overwriting an existing file, write `<name>.chemx-backup` and name it
  in the output.
- Refuse to overwrite a file whose content did not originate from the generator,
  detected by an absence of the generated-file marker, unless `--force` is
  passed.
- `--json` never implies write permission for any command.

### 4.8 Who owns AGENTS.md

Section 4.7 exposes a contradiction with section 5.3. That section proposes
making `AGENTS.md` the single canonical rulebook, with `CLAUDE.md`,
`llms.txt`, and `.cursorrules` generated from it. But `pillars` already
treats `AGENTS.md` as a generated artifact whose source of truth is
`.chemx/config.json`.

Both cannot hold. The repository currently contains a 477-line hand-authored
`AGENTS.md` that the tool considers disposable, which is why it was destroyed
without ceremony.

**Decision required (see section 9).** Two coherent options:

1. **Hand-authored canonical.** `AGENTS.md` is prose owned by the author.
   `pillars` stops generating it and writes only `.chemx/config.json` plus a
   short generated include that `AGENTS.md` references. Preserves the 477 lines
   of reasoning, which carry the argument the rules rest on.
2. **Generated canonical.** Pillar templates become the source of truth and grow
   to hold the full directive text, with `AGENTS.md` entirely generated. Makes
   regeneration safe by definition, but the current templates are a small
   fraction of the existing content, so this means rewriting the directives as
   templates before the tool can be trusted near them.

Option 1 is recommended. The hand-authored document contains arguments, not just
thresholds, and section 5.3 depends on a canonical source that a generator will
not clobber.

## 5. Pass 2: Cost

### 5.1 `audit --json` budget

115,407 bytes today, of which the `patterns` section alone is 28,105 bytes and
`violations` is 45,390.

**Required behavior.** Default output carries: health summary, counts by rule
and severity, and the top 20 violations ranked by severity then file hotspot
density. `patterns`, `roadmap`, `contextAnalysis`, and the full violation array
move behind `--full`. Target under 1,500 tokens by default, asserted by a
byte-budget test.

### 5.2 `team task list` default filter

102,844 bytes today, returning all 530 rows of which 405 are done.

CLAUDE.md instructs agents to query this database *before touching files*, so
the mandated first move of every session costs approximately 25,700 tokens
against a list that is 76% completed work.

**Required behavior.** Default to open and claimed tasks only, capped at 20,
newest first. `--all`, `--status=`, and `--limit=` recover the rest. Target
under 500 tokens by default.

### 5.3 One canonical rulebook

Five documents totalling 13,293 tokens load per session, and they contradict
each other on the tool's single most-cited rule:

| Source | File-length rule |
| :--- | :--- |
| `CLAUDE.md` | 100 lines, hard outer bound |
| `llms.txt` | "Strict File Line Outer Bound (< 100 lines)" |
| `AGENTS.md` | Rejects line caps; 250-line soft warning; 100 only under `--profile=atomic-strict` |
| `.chemxrc` | `"enforce-file-length": false` |
| resolved config | `maxLineCount: 500`, `maxMoleculeLineCount: 100` |

**Decision taken, flagged for confirmation.** AGENTS.md wins. The pragmatic
structural-weight model (complexity 12, hook density 4, render depth 4, prop
surface 7, 250-line soft warning) becomes the single default, with
`--profile=atomic-strict` as the opt-in 100-line mode. Rationale: `.chemxrc`
and the resolved config already behave this way, AGENTS.md argues the position
at length, and a hard 100-line rule would render the tool's own 34,000-line
CLI permanently non-compliant.

**Depends on section 4.8.** This section assumes `AGENTS.md` is hand-authored
and canonical. If the generated-canonical option is chosen instead, the shim
generation described here keys off the pillar templates rather than `AGENTS.md`.

**Required behavior.** One canonical `AGENTS.md` holds the rules. `CLAUDE.md`,
`llms.txt`, and `.cursorrules` become generated host shims, each under 400
tokens, pointing at the canonical source and carrying only host-specific
invocation syntax. A test fails if any shim states a threshold that disagrees
with the canonical document. Target under 2,500 tokens total.

### 5.4 TTY-gated presentation, and the studio seam

The banner, grade art, and hotspot graph account for 11,171 of 12,700 bytes of
`audit` human output.

**Required behavior.** All reporter and banner modules load only when
`process.stdout.isTTY` is true and no `--json` flag is present. Under a pipe or
with `--json`, the presentation layer is never imported.

This is the architectural seam for the agreed `chemx` / `chemx-studio` split.
After this change the import graph already separates engine from presentation,
so promoting it into two packages becomes a packaging exercise rather than a
refactor. That promotion is explicitly out of scope here.

### 5.5 `--help` diet

14,206 bytes today, inlining every flag description for every command.

**Required behavior.** Top-level `--help` lists commands with one-line
summaries, under 1,500 bytes. Full flag detail moves to
`chemx help <command>`.

## 6. Pass 3: Claims

### 6.1 Honest benchmark baseline

`chemx bench` reports 80% average reduction, but its "Traditional Tokens"
baseline is the cost of reading an entire file. That is not the realistic
alternative; a competent agent performs a targeted read. The benchmark's own
Category 2 (Symbol Search) measures against a fairer baseline and reports
52% to 60%.

**Required behavior.** Re-baseline every category against targeted reads
(grep to locate, then read the relevant range). Publish the resulting figure as
the headline even though it will be lower than 80%. A defensible 52% to 60%
survives scrutiny; an 80% built on a straw man does not.

### 6.2 `--enrich` guidance

`--outline --enrich` cuts 3% to 10% on procedural modules (19,575 to 19,036
bytes on `team-triage.js`). The skeleton generator is tuned for component
capsules, where it performs as designed. `CLAUDE.md:19` recommends it as the
general token-minified read mode, which is the one mode that does not save
tokens on most of this codebase.

**Required behavior.** Enforce a budget: if the enriched payload exceeds 40% of
the raw file, omit it and emit a one-line note naming the plain `--outline` and
`--symbol=` alternatives. Correct the guidance in the generated host shims to
scope `--enrich` to component files.

## 7. Testing Strategy

- **Fixture pairs.** `cli/audit/fixtures/<RULE_ID>/should-fire.js` and
  `should-not-fire.js` per rule. The should-not-fire files are seeded from the
  confirmed false positives documented in section 4.
- **Precision gate.** A test runs the full rule set over `cli/` and asserts
  zero violations from any rule whose fixtures declare the construct legal.
- **Gate coherence test.** Asserts `verify` and `audit` return identical grade
  and violation count for an identical explicit scope.
- **Byte-budget tests.** Assert the section 3 criterion 4 ceilings. These fail loudly on
  regression, which is the point: cost is a contract, not an aspiration.
- **Claim tests.** Parse published numbers out of `README.md`, `llms.txt`, and
  `benchmarks/README.md`, re-measure them, and fail on drift beyond tolerance.
- **Scope isolation test.** Boots the MCP server with `cwd` set to a temporary
  directory, issues a relative read against a different project root, and
  asserts refusal rather than cross-project resolution.

## 8. Risks

- **`verify` reports far more debt on this repo.** Expected and desired.
  Fixing 4.4 means the gate finally audits `cli/`, and under the lexicon
  standard the honest control-flow count is roughly 1,867, not 87. The ratchet
  baseline keeps the gate meaningful: existing debt is visible and
  non-blocking, and only counts above baseline fail.
- **Rule exemptions could hide real defects.** Mitigated by fixture pairs: each
  exemption ships with a should-fire case proving the rule still catches the
  pattern it was written for.
- **Pruning tasks loses history.** Mitigated by deleting only open tasks and
  flagging completed ones `suspect_origin` rather than removing them.
- **Some completed tasks may have degraded the code.** Shallow-catch tasks may
  have overridden intentional swallows; control-flow tasks may have introduced
  restatement names. Not addressed here. Pass 1 produces the evidence set; the
  remediation decision is separate and belongs to the user.

## 9. Open Decisions for Review

1. **Line-length policy.** Section 5.3 selects the AGENTS.md pragmatic model
   and demotes `CLAUDE.md` and `llms.txt` to generated shims. Confirm, or
   choose strict 100-line and accept that the kit's own CLI cannot comply.
2. **AGENTS.md ownership.** Section 4.8 requires choosing hand-authored or
   generated canonical. Recommendation is hand-authored. Section 5.3 depends on
   the answer.
3. **Suspect-task audit.** Whether to spot-check the completed shallow-catch
   tasks flagged `suspect_origin` after Pass 1 lands, and at what sample size.
   Completed control-flow tasks are covered by `CONTROL_FLOW_RESTATEMENT_NAME`
   instead.
4. **Pass ordering.** Passes are specified in impact order. Confirm that Pass 1
   ships and is verified before Pass 2 begins, rather than interleaving.
   Within Pass 1, the irreversible-harm fixes (4.7 write gate, 4.5 `cwd`
   resolution, 4.3 triage opt-in) land first, then 4.4 together with the
   lexicon ratchet.
