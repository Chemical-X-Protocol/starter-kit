# Language adapters for the top 25 languages: design spec

Date: 2026-11-01. Epic: #6787 (repo `apps/chemical-x/starter-kit`). Authority: the repository owner, 2026-11-01: make chemx truly language-agnostic and cover the top 25 languages (Python, JavaScript, TypeScript, Java, C#, C++, C, Go, PHP, Rust, Shell, SQL, Kotlin, Swift, Ruby, R, PowerShell, Dart, Lua, Scala, Objective-C, VB.NET, Perl, MATLAB, HCL/Terraform).

This spec is the synthesis of three competing designs (data-first, contract-first, migration/risk-first) and three judge reviews. The migration/risk-first design scored highest overall (7.5, 6.0, 7.5) and is the skeleton: safety rails first, per-capability stages with a kill switch, a synchronous worker bridge for tree-sitter, additive index schema, and grammars built inside the kit repo. Grafted from the data-first design: function-free records validated against a vocabulary, a parametric export rule, data ecosystem records, error-count edit gating, an explicit "ambiguous" detection outcome, and the guard rule that ties guard rollout to a real outline. Grafted from the contract-first design: per-extension grammar selection, the embedded-region contract, implicit-visibility edges, UTF-16 column normalization and the "also found, not verified" rule for nested projects. Section 11 maps every blocking issue the judges raised to the change that fixes it.

All paths are relative to the starter kit unless they start with `apps/` or `wp-content/`. Task status lives in `.chemx/index.db`; this document holds design only. Task keys (P0-1, P3-2, ...) are the ones the orchestrator files under #6787.

## 1. Goals and non-goals

### Goals

1. For every one of the 25 languages, `chemx read --outline`, `--symbol` and `--logic`, index symbols, and import extraction and resolution for `q`, `--blast-radius`, `trace` and `backtrace` run through one generic tree-sitter engine. Symbols carry real line ranges and qualified names. Adding a language is a data record, query files and a fixture module, not new engine code (section 4.16).
2. `chemx test`, `typecheck`, `lint`, `build` and `verify` work in non-JS projects with honest tri-state verdicts. A Go or Python project never FAILs because `node_modules` is missing.
3. The audit dispatches per language. Language-neutral rules run wherever a language's queries provide the captures they need, stay in shadow until measured, and JS-only pillars are declared N/A, never vacuously passed.
4. One extension table drives guards, the delta gate, `chemx d` micro-sync, autofix, clones and test-file detection. Raw `pytest`, `cargo test`, `go test` and similar map to chemx commands. Host shims and the README capability table are generated from the registries.
5. Nothing regresses. JS, TS, Vue, Svelte and PHP output stays byte-identical until a measured flip. A missing grammar package degrades to text-only coverage with a named reason, never a crash. No ratchet baseline changes retroactively when a language is added or its analysis improves.

### Non-goals (this epic)

- Retiring Babel, `@vue/compiler-sfc` or php-parser. Parity is measured (section 6, P9-1); retirement is a later owner decision.
- Forge, heal, explode, capsule generators, capsule mutators, scaffold and test lanes for non-JS languages. They are declared N/A per record and refuse with a named message (section 4.15).
- Type-aware semantics (LSP). An opt-in `--semantic` mode is a follow-up.
- Parsing template languages: ERB, Razor (`.cshtml`, `.razor`), Blade, Jinja HTML, Twig, Helm templates. They get template records with text-only coverage and the reason `template language: not parsed` (section 4.7).
- A vetted VB.NET grammar. VB.NET ships on its own-language regex extractor; its experimental grammar runs in shadow only.
- Planners for Bazel, Buck2, Pants and Meson. They are detected and reported as INCONCLUSIVE with a named reason (section 4.11).
- New hand-written directives in `AGENTS.md` (it is generated by `chemx pillars --write`).

## 2. User decisions (fixed)

1. **Parsing.** `web-tree-sitter` pinned at 0.27.1 (pure WASM), one generic CST plus tree-sitter query engine, a language mostly a data record. `@babel/parser` (JS/TS/Vue/Svelte) and php-parser (PHP) stay until tree-sitter reaches parity on the existing suite. Regex only as a parse-failure safety net and for languages whose grammar is not vetted.
2. **Grammars ship as a separate optional package**, `@chemx/grammars`, every `.wasm` built with one pinned `tree-sitter-cli` 0.27.1 and loaded by one runtime (ABI range 13 to 15), loaded lazily per extension, degrading to status `unavailable` with a named reason when absent. Grammar sources are pinned (scoped or maintained names; the unscoped npm names `tree-sitter-r` and `tree-sitter-hcl` are malicious placeholders) and checksummed in CI.
3. **Scope is everything**: read, index and graph; toolchain runners including detection, commands, output parsers, `--changed` mapping and the `node_modules` hard-fail; audit dispatch with JS-only pillars N/A; guards with one extension table, raw-runner mapping, host shims and a generated capability table. Forge, generators, explode and capsule mutators stay JS-framework features, declared N/A per adapter.

Consequences this spec draws from them:

- `web-tree-sitter` is an exact dependency of `@chemx/grammars`, not of the kit. The kit never imports it directly; it resolves the runtime next to the grammar manifest it chose, so runtime and ABI always travel together and a default kit install stays lean.
- A missing grammar counts as a parse failure for the safety net. The seven languages that have regex rows today (C#, Python, Go, Rust, Java/Kotlin, C/C++) keep those rows, now from own-language extractors, when grammars are absent. Dropping them would be a regression.

## 4. Architecture

### 4.1 Layers

`cli/lang/` holds the registry, records (`records/<id>.js`), detection, stages, schema and vocabulary; it is guard-safe (no parser imports). `cli/treesitter/` is the generic engine behind a synchronous worker bridge, with kit-owned `.scm` queries. `cli/lang/extract.js` is the one per-file entry: it picks the engine per capability and runs the fallback ladder. `cli/resolve/` holds resolvers and implicit edges, `cli/frameworks/` the vue, svelte, react, capsules and wordpress plugin records, `cli/toolchain/` the ecosystem records, ownership, readiness, planning, output parsing and `--changed`, and `grammars/` the `@chemx/grammars` package source (inside the kit repo, published separately). Consumers (index, reader, graph, edit gate, audit, toolchain, guards, docs) call the registry and `extract.js`. None of them branches on a language id or keeps an extension list.

### 4.2 The language record

A language is one file, `cli/lang/records/<id>.js`, exporting `Object.freeze({...})`. Records are plain data: no functions, no `RegExp` objects (regexes are source strings), no class instances. `cli/lang/schema.js` rejects anything else, along with unknown keys, unknown vocabulary values, and globs, regexes or hook names that do not compile or resolve. The contract lives in `cli/lang/types.d.ts`; `LanguageId` is a string matching `/^[a-z][a-z0-9]*$/`, not a closed union.

```ts
interface LanguageRecord {
  id: string; name: string; version: number;          // version bumps when the record or its queries change meaning
  legacyId?: 'jvm' | 'cpp';                            // facade id until the coverage bucket switch (P4-1)
  reportAs?: string;                                   // coverage and ratchet bucket key
  files: {
    extensions: string[]; filenames?: string[]; paths?: Glob[]; shebangs?: string[];
    ambiguous?: Record<string, { markers: { re: RegexSource; weight: number }[]; minScore: number; tieBreak?: TieBreak[] }>;
    exclude?: Glob[]; declaration?: Glob[]; generated?: Glob[]; generatedMarkers?: RegexSource[];
    vendorDirs?: { name: string; when: 'always' | 'project-root' | { sibling: Glob } }[];
    tests: { names: Glob[]; dirs?: string[]; contentMarkers?: RegexSource[] };
    regions?: HookName;                                // embedded-language splitter (section 4.7)
    dialects?: { default: string; byExtension?: Record<string, string> };   // SQL
  };
  syntax: {
    lineComment: string[]; blockComment: { open: string; close: string; nests?: boolean }[];
    docString?: { open: string; close: string }[];
    strings: { open: string; close: string; escape: string | null; raw?: boolean; multiline?: boolean }[];
    blockStyle: 'brace' | 'indent' | 'end-keyword' | 'paren' | 'none';
    blockOpeners?: string[]; endKeywords?: string[]; keywords: string[]; qualifier: '.' | '::' | '\\';
  };
  parse: {
    grammar?: string | Record<string, string>;         // '.tsx' -> 'tsx', '.tf' -> 'terraform', '.hcl' -> 'hcl'
    queries?: string; inheritQueries?: string[];       // cpp and objc inherit c; tsx inherits typescript
    grammarStatus: 'vetted' | 'experimental' | 'none';
    errorPolicy: 'report' | 'coverage-only'; maxBytes?: number; timeBudgetMs?: number;
  };
  engines: Record<'index' | 'outline' | 'symbol' | 'logic' | 'audit' | 'editGate', Engine>;
  stages: Partial<Record<Capability, Stage>>;          // section 4.4
  fallback?: string;                                   // own-language regex module in cli/lang/fallback/
  symbols: { exportRule: ExportRule; memberKinds?: Partial<Record<SymbolKind, SymbolKind>>;
             constructorRule?: { names?: string[]; nameEqualsContainer?: boolean }; indexKinds?: SymbolKind[] };
  imports: { resolver: string; options?: ResolverOptions; normalize?: HookName; implicitEdges?: HookName[] };
  layout: { tiers?: { glob: Glob; tier: Tier }[]; entryPoints?: Glob[]; viewMarkup?: boolean };
  ecosystems: string[];
  audit: { analysisRevision: number; passes: PassName[]; analyzer?: HookName; defaultOff?: string[];
           droppedTextRules?: string[]; envAccess?: RegexSource[]; fakeGreen?: RegexSource[]; deltaGate?: boolean };
  notApplicable: Partial<Record<NaFeature, string>>;    // feature -> reason shown to the user
}

type Engine = 'babel' | 'sfc' | 'php-parser' | 'csharp-heuristic' | 'tree-sitter' | 'regex' | 'legacy-polyglot' | 'text';
type Capability = 'source' | 'index' | 'outline' | 'imports' | 'resolve' | 'editGate' | 'audit' | 'guard';
type Stage = 'off' | 'text' | 'shadow' | 'on';
type ExportRule =
  | { kind: 'all' } | { kind: 'top-level-only' } | { kind: 'capture' }
  | { kind: 'name-not-prefix'; prefix: string } | { kind: 'name-capitalized' }
  | { kind: 'modifier'; anyOf: string[]; noneOf?: string[]; default: boolean };
```

`ExportRule` is parametric so a new language usually needs data, not code: Go is `name-capitalized`, Python and Dart `name-not-prefix '_'`, Rust `modifier ['pub'] default false`, Java and C# `modifier` with their defaults, shell, SQL, HCL, MATLAB, R and Lua `top-level-only`.

`cli/languages.js` becomes a facade over the registry with the same exports and the same `LANGUAGE_DEFINITIONS` keys as today (`jvm` and `cpp` stay until P4-1). The object stays a mutable plain object until the two specs that monkeypatch it move to the `registerTestLanguage(record)` / `resetTestLanguages()` seam in the same task (P0-6). A facade-equivalence spec captured before the change pins `getLanguageByExtension`, `getLanguageForFile`, `isSourceFile` and `isBabelParsable` over a path table. `isSourceFile` keeps today's test-name rule until P1-10. P0-5 exports the 13 existing records as `LANGUAGE_RECORDS` from `cli/lang/records/index.js`; kotlin's `grammarStatus` is `experimental`, every other record with a grammar is `vetted`.

### 4.3 Detection

`languageForPath(relPath, { content?, map? })` tries, in order (`map` is the `.chemxrc` `languages.map`, passed in so detection stays pure):

1. exact extension (lowercase), then exact basename (`Gemfile`, `Rakefile`, `Jenkinsfile`);
2. `languages.map` globs (for example `{ "bin/*": "shell" }`), checked before the records' `files.paths` globs;
3. shebang, read only for extensionless files (first 8 KB), with `/usr/bin/env X` unwrapped;
4. for an ambiguous extension (`.h`: c, cpp, objc; `.m`: objc, matlab; `.t`: perl only when confirmed), weighted content markers over the first 8 KB, then the project tie-break (a `.h` beside `.cpp` files or under a C++ CMake project is cpp; under `Package.swift` or an Xcode project it is objc; a `.m` beside `buildfile.m` or a `*.prj` is matlab);
5. otherwise ambiguous: no language, text-only with reason `ambiguous-extension`.

The guard is content-free for latency. It classifies by extension, basename and path glob only, and treats an ambiguous extension as guarded when any candidate is guarded. Extensionless shebang scripts are therefore guarded only when a path glob names them; this is a stated limit.

### 4.4 Stages, engines and the kill switch

Every capability of every language moves `off -> text -> shadow -> on`:

| Stage | Meaning |
| :--- | :--- |
| off | Not a source language for this capability |
| text | Today's behavior exactly (the polyglot regex, the C# heuristic analyzer, or text-only) |
| shadow | Today's output; when shadow logging is on (`.chemxrc` `languages.shadow` or `CHEMX_LANG_SHADOW=1`) the new engine also runs and diffs go to `.chemx/parity/*.jsonl` |
| on | `engines[capability]` is authoritative |

For JS, TS, Vue and Svelte the engines are `babel`/`sfc` at stage `on`, which is today's path. `cli/lang/rollout.js` `effectiveStage(lang, capability, root)` resolves the record default, then `.chemxrc` `languages` (`stages`, `shadow`, `requireGrammars`, `disable`), then `CHEMX_LANG_STAGE=<lang>:<cap>=<stage>`, then the kill switch `CHEMX_LANG_ENGINE=legacy`, which restores the pre-program path for every capability by clamping only the `tree-sitter` and `regex` engine slots. `requireGrammars` currently means `grammarStatus === 'vetted'`. Each stage flip is a one-file commit to that language's record plus its own spec.

### 4.5 Normalized rows and the capture vocabulary

All engines (Babel, php-parser, tree-sitter, regex) produce the same rows, so outline, `--symbol`, index, trace and the edit gate are one code path.

```ts
interface SymbolRow { name: string; kind: SymbolKind; startLine: number; endLine: number; startColumn: number;
  signature: string; isExport: boolean; visibility: Visibility | null; container: string | null;
  qualifiedName: string; depth: number; isMember: boolean; docStartLine: number | null;
  language: string; engine: Engine; confidence: 'ast' | 'heuristic' }
interface ImportRow { specifier: string; kind: ImportKind; names: string[]; alias: string | null;
  line: number; isTypeOnly: boolean; confidence: 'ast' | 'heuristic' }
interface Extraction { language: string; engine: Engine;
  status: 'ok' | 'partial' | 'error' | 'minified' | 'skipped' | 'unavailable' | 'heuristic' | 'text';
  reason: string | null; errorCount: number; firstError: { line: number; column: number; message: string } | null;
  symbols: SymbolRow[]; imports: ImportRow[]; fingerprint: string }   // `${id}@${version}:${engine}:${grammarSha8|'-'}:${stage}`
```

Lines are 1-based. Columns are UTF-16 code units, the unit comment regions, suppressions and violations already use. With string input web-tree-sitter already reports `startIndex` and `Point.column` in UTF-16 code units, so the engine must not convert points (converting again corrupts columns), and a non-ASCII fixture asserts that no conversion happens (spike note section 2). `SymbolKind` is the `SYMBOL_KINDS` vocabulary in `cli/lang/vocab.js`, including the container-only kinds `impl extension block`; the capture names below are `CAPTURES` there. `q --kind` gets an alias map (`class` matches class, struct, interface, trait, protocol, record; `function` matches function, method, constructor, procedure).

Kit-owned queries live in `cli/treesitter/queries/<dir>/`, seeded from each grammar's upstream `tags.scm`:

| File | Captures |
| :--- | :--- |
| `tags.scm` | `@definition.<SymbolKind>`, `@name`, `@body`, `@doc`, `@export`, `@visibility`, `@modifier`, `@container.<impl/extension/block>`, `@reference.type`, `@entry`; `#set! chemx.kind`, `#set! chemx.skip` |
| `imports.scm` | `@import`, `@import.source`, `@import.source.system`, `@import.name`, `@import.alias`, `@import.wildcard`, `@import.mod`, `@import.type-only`, `@import.dynamic`; `#set! chemx.importKind` |
| `calls.scm` | `@call`, `@call.name`, `@call.receiver` |
| `syntax.scm` | `@comment`, `@comment.doc`, `@string` |
| `audit.scm` | `@scope.function`, `@branch`, `@logic`, `@nest`, `@ternary`, `@catch`, `@catch.body`, `@catch.swallow`, `@exec`, `@log`, `@flow.return`, `@flow.throw`, `@flow.loop` |

A missing file means the capability is not provided (`no-query`). Unknown capture names fail the conformance spec and are ignored with a debug note at runtime.

Capture to row mapping: definitions are sorted by (start ascending, end descending) and walked with a containment stack to give `container`, `qualifiedName` (joined with `syntax.qualifier`), `depth` and `isMember`. `signature` is the source from the definition start to `@body` (or the end of the first line), whitespace collapsed, at most 200 characters. `docStartLine` extends over contiguous comments and decorators, attributes or annotations, so a decorated Python function or an annotated Java method is sliced whole. Rows are deduplicated on (kind, name, startLine). Imports are grouped by the `@import` node; Rust use-trees are flattened by the `rust-use-tree` normalizer hook. Containers such as `impl Repo for MemRepo` name members `MemRepo::get`.

### 4.6 Engine: the synchronous bridge

Every chemx extraction entry point is synchronous (`extractAstMetadata`, `generateAstOutline`, `parseSource`, `applyEdits`, `syncSearchIndex`, `auditFileDetailed`), while `web-tree-sitter`'s `Parser.init` and `Language.load` are async. Tree-sitter therefore runs in one lazily spawned `worker_thread`, and `cli/treesitter/bridge.js` makes it look synchronous: post `{ id, op, payload }` on a `MessagePort`, `Atomics.wait` on a `SharedArrayBuffer` flag with the per-call timeout, then `receiveMessageOnPort`. Consequences:

- No call site changes shape, so there are no prime sites to miss: CLI commands, MCP calls (including stale-mode `fresh-entry.js`), the offload and scorecard workers, the post-edit hook (stdin payload), the public subpath exports `./audit`, `./reader`, `./search`, `./patcher`, the patcher repair path and the `task done` audit all reach the engine the same way.
- A parse that exceeds `timeBudgetMs` (default 2,000 ms per file) is cancelled inside the worker through `progressCallback` and returns `skipped: 'timeout'`, keeping the compiled grammars (spike: 238 ms for a 200 ms budget). The bridge's `Atomics.wait` timeout is a backstop at `timeBudgetMs + 1000` ms that terminates the worker, for a stuck external scanner that `progressCallback` cannot interrupt; the next request spawns a fresh worker (117 ms).
- WASM linear memory never shrinks, so the worker is recycled when its `process.memoryUsage().external` (WASM memory) exceeds 256 MB, checked after each op; RSS is not the trigger (spike note section 5). Recycling discards compiled grammars; their recompile cost is part of the budget in section 7.
- The worker is unref'd and spawned only on the first tree-sitter op. A JS-only `q`, `read`, `audit` or `check` never starts it. The guard never imports the bridge.
- Trees never cross the bridge. Payloads are the file content and a small options object; results are plain rows. Ops on one parse (`symbols imports calls comments syntax logic metrics audit`) share the tree, which is deleted in `finally`.
- Inside the MCP offload worker the bridge spawns a nested worker, which Node allows. An in-process MCP call blocks the server thread for at most one file's budget; heavy actions already run in the offload worker (`cli/mcp/offload.js` `OFFLOADED_ACTIONS`).

**Decision (P0-8, spike note `2026-11-02-treesitter-engine-spike.md` sections 2 to 4).** Plan A, this bridge, holds. The spike ran 0.27.1 (`Parser.init`, `Language.load`, `Query` predicates and `#set!`, `progressCallback` cancellation, `tree.delete()`) and measured a round trip p50 of 0.016 ms against the 0.5 ms criterion, stable when nested under the offload worker (5 of 5 runs, no leaked threads after abort or timeout). The bridge exists because guards and JS-only commands must not load `web-tree-sitter` and because `progressCallback` cannot interrupt a stuck external scanner in-thread, not because in-thread synchronous use is impossible: a top-level `await` of `Parser.init` would allow it. The worker must import the ESM entry `web-tree-sitter.js`; the CJS build exports stale `LANGUAGE_VERSION` snapshots. **Plan B** (the documented fallback, not needed) is an async prepare step: a sync call on an unprepared language returns `unavailable: 'not-prepared'` and increments a counter, and a spec drives every boundary over a polyglot fixture expecting zero such outcomes. The plan B boundary list is complete: `cli/main.js` dispatch and its API wrappers, `executeMcpTool` in `cli/mcp/tools.js` (covers `fresh-entry.js`), `cli/mcp/offload-worker.js`, `cli/mcp/scorecard-worker.js`, `cli/hooks/run-hook.js` (targets from the stdin payload), the subpath export modules (`cli/audit.js`, `cli/search.js`, `cli/patcher.js`, and `cli/reader.js` through P3-3, each gaining an async `prepare` export), the `cli/patcher-cli.js` repair path and `cli/team/audit-run.js`. Plan B would add task P3-9; nothing else in the plan changes.

**Loading.** The worker imports `web-tree-sitter` from the chosen grammars directory, runs `Parser.init` with `locateFile` pointing at the runtime wasm, and per grammar on first use: checks the sha256 (section 4.8), `Language.load(bytes)`, checks the ABI, then compiles each query once. Failures map to named reasons (`checksum-mismatch`, `abi-mismatch`, `load-error`, `query-error:<dir>/<file>:<row>`) and are never thrown. `grammars-not-installed` is not memoized, so an install during a long-lived MCP process is picked up.

**Parsing.** Exclusions and declaration files first, then the minified heuristic shared with `php-parse.js` (over 64 KB and mean line over 200), `maxBytes` (default 1 MiB, 512 KiB for perl, `too-large`), then a lookup in an Extraction LRU (4 MB of source, results not trees, keyed by content sha1 plus fingerprint plus ops). ERROR and MISSING nodes give `errorCount` and `firstError`. Status is `partial` when errors exist and definitions were found, `error` when the root is ERROR or nothing was found.

**Fallback ladder** (per file and per capability, in `cli/lang/extract.js`):

1. Stage below `on`: today's path.
2. Primary engine (`babel`, `php-parser` unchanged; `tree-sitter` through the bridge). `ok` and `partial` are used; the outline appends `note: N syntax errors from L12, kept partial tree`.
3. Own-language regex (`cli/lang/fallback/<id>.js`) when tree-sitter is unavailable or the parse is `error`. It runs on text-lexer-masked content (comments and strings blanked), produces real line numbers, tags rows `confidence: 'heuristic'`, and the outline prints `(regex fallback: <reason>)`. It serves index, outline and `--symbol` only, never audit AST rules, the edit gate or resolution.
4. Text-only with the named reason. Block extents for `--symbol` come from `cli/lang/text-blocks.js` by `blockStyle` (indent for Python, end-keyword for Ruby, Lua, MATLAB, VB; brace with masking otherwise), which replaces the brace counter at `reader.js:145-171`.

There is no cross-language regex pass anywhere; `extractRegexFallback` is deleted when the index cuts over (P3-2). Babel parse failures keep today's behavior and never fall to another language's patterns.

### 4.7 Embedded regions

`files.regions` names a splitter hook returning `{ language, startLine, startColumn, content }[]`; `extract.js` parses each region with its own language's engine and maps lines back to the host file. Splitters in this epic:

- `regions-ipynb`: `.ipynb` code cells as Python, lines mapped to the JSON line of each source string.
- `regions-rmd`: fenced chunks in `.Rmd` and `.qmd` (R and Python).
- `regions-jinja-sql`: dbt models; Jinja tags are blanked with whitespace that keeps lines and columns, and `ref()`/`source()` become imports through the `dbt-refs` normalizer.
- `regions-tsql-batches`: T-SQL `GO` separators split the file into batches.

Vue and Svelte keep the SFC engine; a regions adapter over the existing `cli/sfc` preprocess serves only the tree-sitter shadow path. PHP needs no splitter: the HTML-aware `php` grammar (not `php_only`) is used for every `.php` file, because WordPress templates and partials mix inline HTML with `<?php ?>` blocks and `php_only` cannot parse them. Template languages are records with every engine `text` and the reason `template language: not parsed`; they are source `off` by default.

### 4.8 Grammar package

`@chemx/grammars` is built in `grammars/` inside the kit repo and published separately; no new git repo or submodule. The kit's `package.json` `files` whitelist does not include it.

- `grammars/package.json`: `dependencies: { "web-tree-sitter": "0.27.1" }` exact, no install scripts, `files: ["index.js", "index.d.ts", "manifest.json", "wasm/", "LICENSES/", "SOURCES.md"]`, version `1.N.0` bumped by hand (the CalVer auto-bump must not touch it).
- `grammars/grammars.lock.json` (committed source of truth): the `tree-sitter-cli` 0.27.1 release asset URL and sha256, the sha256 of the wasi-sdk 34 and binaryen 132 release assets, our builder image digest (`node:22-trixie-slim@sha256:2117f713a417f3aff682ac8f5bc2ebbdf1beed51f36e67ab1e0fd3866b6d2d8f`), and per grammar key `{ repo, tag, commit (40 hex), archiveSha256, subdir, generate, license, upstreamVersion, tier: 'core' | 'extended' | 'experimental' }`.
- `grammars/allowlist.json`: allowed upstream repos and a denylist of npm names: unscoped `tree-sitter-r`, `tree-sitter-hcl` (malicious placeholders), stale unscoped `tree-sitter-kotlin`, `-lua`, `-sql`, `-matlab`, and `tree-sitter-wasms` 0.1.x (built with CLI 0.20).
- `scripts/fetch.mjs` downloads the git archive at the pinned commit and checks `archiveSha256`; it never runs `npm install` (every `tree-sitter-<lang>` package runs node-gyp at install). `scripts/build.mjs` downloads the checksum-verified CLI, pre-fetches the two lock-pinned toolchain assets, runs `tree-sitter generate` where the lock says so (SQL, Swift, Perl: SQL under the node JS runtime because QuickJS fails on an implicit global in its `grammar.js`; Perl because v2.0.3 has no `src/parser.c` at its tag), then `tree-sitter build --wasm` in our digest-pinned builder container with `--network none` and `TREE_SITTER_WASI_SDK_PATH` and `TREE_SITTER_BINARYEN_PATH` set. tree-sitter-cli 0.27.1 compiles with wasi-sdk 34 clang and optimizes with binaryen 132 `wasm-opt`, not emscripten; it downloads both into `~/.cache/tree-sitter` without a checksum step when unconfigured and starts no container itself, which is why the lock pins them and the script supplies them (spike note sections 1.1 and 1.2). Pre-generated grammars keep their upstream generator's ABI (python's `parser.c` is from CLI 0.25.9, ABI 15), so the manifest records each grammar's `abiVersion` as read from `Language.load`. It writes `manifest.json` `{ format: 1, cli: '0.27.1', runtime: '0.27.1', grammars: { key: { file, bytes, sha256, abiVersion, commit, license } } }`. `scripts/verify.mjs` (CI) rehashes every wasm against the manifest, checks every entry against the lock and allowlist, loads every wasm in `web-tree-sitter` 0.27.1, and compiles every kit query against its grammar.
- Determinism: the four spike grammars were byte-identical across two container runs, so CI expects equality and reports any difference; the double-build comparison stays advisory. The trust root is the CI-built manifest, published with npm provenance, and the kit's own `cli/lang/grammars-lock.json` (package version, CLI, runtime, ABI, and sha256 plus bytes per grammar it was tested with).
- Tiers: core = python, javascript, typescript, tsx, java, c_sharp, c, cpp, go, php, rust, bash. Extended = sql, swift, kotlin, ruby, r, powershell, dart, lua, scala, objc, perl, matlab, hcl, terraform. Experimental = vb_dotnet. A later split into several packages must keep manifest keys.
- Publishing needs the owner's go-ahead (section 12); until then CI uploads the built `wasm/` as an artifact.

Resolution in `cli/treesitter/grammar-locate.js` (fs only, no wasm read, cached per process; first hit wins, each miss recorded as a reason):

1. `CHEMX_GRAMMARS_DIR` (a directory with `manifest.json`): trusts that directory's manifest; a notice line names the mode.
2. `.chemxrc` `languages.grammars`.
3. `createRequire(<projectRoot>/package.json).resolve('@chemx/grammars/manifest.json')`.
4. The same resolve from the kit (`import.meta.url`), which covers a global install and the kit's devDependency.
5. The sibling source checkout `<kitRoot>/grammars/manifest.json` with `wasm/` built: how the global `chemx` linked to the kit source in this monorepo finds a Docker-built tree. Trusts that manifest, with the notice.
6. None: `unavailable: 'grammars-not-installed'`, hint `npm i -D @chemx/grammars`.

For steps 3 and 4 each grammar's sha256 must equal `cli/lang/grammars-lock.json`, else `grammar-checksum-mismatch` for that grammar. The kit declares `peerDependencies: { "@chemx/grammars": "<exact>" }` with `peerDependenciesMeta.optional`, and an exact devDependency once the first version is published (P9-3).

### 4.9 Index, resolution and edges

**No `INDEX_VERSION` bump.** The schema grows only through `COLUMN_MIGRATIONS` in `cli/search-schema-ddl.js` plus a per-row fingerprint, so old and new chemx processes sharing `.chemx/index.db` cannot wipe each other:

- `files.language`, `files.extractor` (the Extraction fingerprint), `files.parse_status`;
- `symbols.container`, `qualified_name`, `visibility`, `depth`, `engine`, `confidence`;
- `imports.kind`, `alias`, `resolution`;
- new `import_targets(importer_path, line, source_module, imported_symbol, target_path, status, via, confidence)` for one-to-many targets; `imports.resolved_path` keeps the first resolved target for old readers;
- new `module_keys(path, key)`.

`index-row-check.js` re-parses a row when its `extractor` differs from the current fingerprint for its language, so installing grammars, a record version bump, a grammar sha change or a stage flip re-parses only that language. Rows written by an older chemx carry `NULL` and are re-parsed once. `ensureIndexVersion` (P0-3) wipes only when the stored version is lower; a higher stored version returns `{ reset: false, foreign: true }` and the sync is skipped with a notice.

**Resolvers** are modules `cli/resolve/<name>.js` implementing:

```ts
interface Resolver { name: string; revision: number; deferred: boolean; reresolveOn: 'never' | 'file-set-change';
  context(root: string, importerRel: string): ProjectContext;   // cached per nearest manifest path + mtime
  moduleKeys(rel: string, ctx: ProjectContext): string[];
  resolve(importerRel: string, row: ImportRow, ctx: ProjectContext):
    { status: 'resolved' | 'external' | 'stdlib' | 'unresolved-local' | 'ambiguous'; targets: string[] };
  isLocal(specifier: string, ctx: ProjectContext): boolean }
```

Resolvers: `js` (today's `search-resolve.js` and `sfc/module-aliases.js` logic moved verbatim; the `@/` default applies to JS only), `path-probe` (data driven: Lua, Ruby `require_relative`, Perl, R `source()`, shell `source`, PowerShell dot-sourcing, Dart relative and `package:`, HCL local module `source`, dbt refs), `python` (dotted relative, absolute, src layout, `__init__.py` keys), `c-include` (quote vs angle, same dir, `compile_commands.json` and CMake include dirs), and the deferred ones resolved in a post-pass of the sync via `module_keys`: `go-module`, `rust-crate`, `jvm-package`, `dotnet-namespace`, `php-psr4`. Contexts are per subproject, never per root only. Adding or moving files re-resolves rows whose resolver declares `file-set-change`.

**Implicit and declared-name edges.** Several languages see other files without imports. Hooks in `cli/resolve/implicit/<name>.js`, listed in `imports.implicitEdges`, add edges with `via: 'implicit'` and `confidence: 'heuristic'`, capped at 200 per file: `same-package-decl` (Go package clause in a dir; Java, Kotlin and Scala package declarations, which for Kotlin need not match the directory), `same-namespace` (C#), `same-module-target` (Swift target directory), `header-impl` (`foo.h` and `foo.c`/`.cpp`/`.m`), `autoload-constant` (Ruby Zeitwerk constant to path), `terraform-dir` (a directory is a module), `conftest-fixture` (pytest `conftest.py` in ancestor directories), and `declared-name` (a `@reference.type` or `@call.name` that names a symbol declared exactly once in the same owning project). Blast radius includes heuristic edges and labels them; import coverage reports resolved, unresolved-local and heuristic counts per language, using the index root, never `process.cwd()`, and never a false 100%.

### 4.10 Edit gate

`parseSource` returns `{ kind: engine, ok, errorCount, error, declarations }` for every engine whose `editGate` stage allows it. `apply-edits.js` refuses when `after.errorCount > before.errorCount` (with the new error lines), which generalizes `wasBroken` and keeps JS byte-identical (Babel strict gives 0 or 1). `declarationDelta` runs for any parse that returns declarations (depth-0 SymbolRow names), not only `kind === 'babel'`. Tree-sitter starts in shadow: would-refuse events go to `.chemx/parity/edit-gate.jsonl` and nothing is refused. A grammar with `grammarStatus: 'experimental'` never gates. An unavailable grammar keeps `unchecked` with a note. Optional native syntax checks (`python -m py_compile`, `gofmt -e`) are a follow-up second stage like the V8 check.

### 4.11 Toolchain ecosystems

An ecosystem is a data record `cli/toolchain/ecosystems/<id>.js` plus optional named hooks, listed statically in `cli/toolchain/ecosystems/index.js`:


**npm is one record among many.** Its `planner: 'npm-legacy'` hook calls today's `planTestCommand`, `planTypecheck`, `detectLintCommand` and `detectProjectBuildCommand` unchanged, and its parser id `node-legacy` calls today's `test-output.js` and `test-failures.js`. Nothing in `plan.js`, `output.js`, `readiness.js` or `owners.js` mentions `node_modules`, vitest or tsc. The PHP harness (`tests/run-tests.mjs`) is the `php-harness` record with the highest priority in its directory, keeping `verify-harness.js` behavior.

**Ownership** (`cli/toolchain/owners.js`). Walk up from the file's directory to the chemx root; the nearest directory with any marker owns the file; every ecosystem with a marker there is an owner, ordered by marker priority, and for a single file the owner whose `languages` include the file's language runs its tools. A Go module nested in a pnpm repo owns its `.go` files. Workspaces (`go.work`, Cargo `[workspace]`, `settings.gradle`, `.sln`, Maven modules, pnpm/npm, uv) make commands run from the workspace root scoped to the member (`cargo test -p crate`, `gradle :module:test`, `go test ./member/...`). Nested projects of other ecosystems below the scope are not run silently: verify prints `also found: go project at services/api (not verified; add it to .chemxrc verify.projects or run chemx verify --all-ecosystems)`.

**Build-system override.** A `build-system` record detects `MODULE.bazel`, `WORKSPACE(.bazel)`, `BUCK`/`.buckconfig`, `pants.toml` and `meson.build` at or above the scope. Inside such a tree, test, typecheck and build are INCONCLUSIVE with `build system <name> is not supported; set .chemxrc toolchain.<kind>` instead of guessing a per-language ecosystem the repo does not use. Nx and Turborepo stay npm scripts.

**Readiness** replaces `checkNodeModules` at its four call sites. npm keeps today's message and FAIL exactly. Python probes `{launch} -c "import pytest"` (a system-wide pytest in a container counts), else INCONCLUSIVE with the hint `uv sync` or `python -m venv .venv && pip install -e .[test]`. Composer needs `vendor/`, bundler `Gemfile.lock` plus `bundle check`, dotnet `obj/project.assets.json`, terraform `.terraform/`; go, cargo, maven, gradle, sbt, swiftpm and pub fetch their own dependencies. A directory with no ecosystem is INCONCLUSIVE `no ecosystem detected (looked for: <markers>)` for test and typecheck; lint keeps its micro fallback.

**Planning**, first applicable wins: the custom `-- <cmd>` (unchanged, except that a recognized tool gets its own filter flag from the guard entries: pytest `-k`, go `-run`, rspec `-e`, dotnet `--filter`; unknown tools keep `-t`, so `test-command.spec.js` stays green); `.chemxrc` `toolchain.<eco>.<kind>`; the record's planner hook; the first `CommandSpec` whose `when` holds, with `{launch} {bin} {targets} {name} {nameRegex} {class} {classes} {pkgs} {crate} {project} {n} {buildDir} {files}` expanded; else INCONCLUSIVE NOT_APPLICABLE. Execution goes through the existing `build/executor.js`.

**Output.** Machine formats are preferred: JUnit XML is the shared format (pytest `--junitxml`, surefire, gradle, sbt, ctest `--output-junit`, bats, Pester, busted, testthat, phpunit `--log-junit`, swift `--xunit-output`), plus TRX, TAP, `go test -json`, Dart JSON and a JSON-diagnostics hook driven by table data. Report files are read only when newer than the run start. Regex tables cover summaries and compiler diagnostics (gcc-style, msbuild, javac-maven, kotlinc, rustc-short, mypy, pyright, ruff, cargo-test). `test-output.js` classify is unchanged, so "no counts and exit 0" stays INCONCLUSIVE; a passing pytest run now has counts. `parseTypecheckOutput` keeps its shape for forge heal-typecheck. Every parser fixture is real output captured by `scripts/capture-toolchain-fixture.mjs` in a digest-pinned Docker image, stored verbatim in `cli/fixtures/toolchain/<parser>.fixtures.js` with the tool version and command.

**`--changed`.** Test identity comes from record `files.tests`, not `SPEC_FILE`. Blockers are the union of the owning ecosystems' `unprovable` globs plus today's JS lists. Strategies: `import-graph` over index edges (npm keeps its current specifier scan as its source), `package` (Go: the changed package plus importer packages), `module` (cargo crate, Maven/Gradle module, dotnet project via ProjectReference), `colocated` (templates such as `lib/{rel}/{stem}.rb -> spec/{rel}/{stem}_spec.rb`), `full`. **Verify** plans per (project, ecosystem): the audit once, then readiness, typecheck, test and optional build per pair, labels from `CommandSpec.label` (no hardcoded `TypeScript`), job-line keys `${kind}:${ecosystem}:${projectRoot}`. **Default scope and config.** `resolveTargetDir` (`path-scope.js`) and the `syncSearchIndex` default use ownership: a cwd owned by a non-npm ecosystem defaults to `.` (vendor dirs and git-tracked filtering keep the walk honest); the .NET special case becomes the dotnet record; npm-owned and unowned directories keep today's `src` guess (section 12 asks whether to drop it per #2037). `config/loader.js` adds embedded config after `.chemxrc` and `package.json`: `pyproject.toml` `[tool.chemx]`, `Cargo.toml` `[package.metadata.chemx]`, `composer.json` `extra.chemx`, read with `toml-lite`. `project-markers.js` gains every ecosystem marker that is not a glob.

### 4.12 Audit

**Dispatch** (`cli/audit/lang-dispatch.js`). `collectRawViolations` runs the universal text passes first (now record-aware), then the analyzer for `engines.audit` at the effective stage: `babel`/`sfc` (today's path, untouched), `php-parser` (`analyzePhp`, untouched), `csharp-heuristic` (today's regex analyzer, coverage reason `heuristic analyzer (regex)` instead of `no AST parser`), `tree-sitter` (query passes through the bridge), or `text`. Every analyzer returns `{ kind, reason, engine, commentRegions, fileHeaderEndLine }`, so suppressions and header exemptions work for every language. The `isPhpPath`, `id === 'csharp'` and `isBabelParsable` branches in `rules.js` go away. `report` and `finalize` are extracted from `php-analyzer.js` into `cli/audit/pass-runner.js` and shared.

**Neutral and JS-only rules.** Query passes emit the existing neutral ids when the language's `audit.scm` provides the captures: COMPLEXITY_CYCLOMATIC_HIGH and STRUCTURAL_WEIGHT_EXCEEDED (php-metrics formulas over `@scope.function`, `@branch`, `@logic`, `@nest`), ERROR_SWALLOWED_EXCEPTION and AI_SLOP_SHALLOW_CATCH, CONTROL_FLOW_NESTED_TERNARY, SECURITY_DYNAMIC_CODE_EXECUTION, the logging ids, and TEST_FAKE_GREEN from record data. SYNTAX_PARSE_ERROR is emitted only with `errorPolicy: 'report'`, which no tree-sitter language has until measured. Babel visitor families, template rules, Tailwind, hook-shape, render depth, VIEW_MONOLITH, molecule budgets, timer and lifecycle rules and Zero-Raw-DOM stay JS or framework rules.

**Applicability** (`cli/audit/rule-applicability.js`) is derived, never hand-kept: a rule applies to a language when a text pass emits it and it is not in `droppedTextRules`, or a pass of that language's analyzer or attached framework declares it and its required captures are in the compiled `audit.scm`. The same table gives `emittable(analyzer, ext)` for ratchet adoption. A pillar is `n/a` for a language when every rule mapped to it in `rule-pillars.js` is inapplicable; `zeroRawDom`, `tableOfContentsViews` and `composableContracts` are N/A for every non-JS language. Reports gain `coverage.byLanguage[L].pillars`; the health score excludes N/A pillars; the `recommended` preset enables UI pillars only when a vue, svelte or react framework is detected.

**Precision.** A query pass emits a rule for a language only when `cli/lang/precision/<id>.json` records `{ defaultOn: true, corpus, heldOut, measured }` at the 80% bar of the PHP spec, or the user's config enables it. Otherwise hits are counted in shadow and shown with `chemx audit --shadow`. `cli/audit/lang-rule-defaults.js` holds the PHP table verbatim and generalizes `PHP_DEFAULT_OFF` and `PHP_DROPPED_TEXT_RULES`. Measuring needs labelled corpora; section 12 asks how to obtain them for languages absent from the monorepo.

**Inconclusive** (`cli/audit/inconclusive.js`). `AST_PARSERS` and the `language === 'php'` special case are replaced by `declaresAst(lang)` (effective audit engine in babel, sfc, php-parser, tree-sitter at stage `on`). A declaring language is inconclusive when coverage is not `ast`/`empty` because of `--fast`, a root parse error, minified, timeout, or a broken grammar (`checksum-mismatch`, `abi-mismatch`, `load-error`, `query-error`). It is not inconclusive for `grammars-not-installed` or `stage text`: those are conclusive text-only with the reason printed, unless `.chemxrc` `languages.requireGrammars` or `CHEMX_REQUIRE_GRAMMARS=1` is set (CI sets it). PHP keeps today's semantics. Coverage gains an `engine` field. The language buckets switch from `jvm`/`cpp` to `java`, `kotlin`, `c`, `cpp` in one commit (P4-1) that updates `coverage-language.spec.js`.

**Ratchet** (three mechanisms, so adding a language or improving its analysis never loosens or tightens an old baseline retroactively):

1. **Freeze** (P0-1). `LEGACY_LANGUAGES` becomes the literal `['.c','.cc','.cjs','.cpp','.cs','.cxx','.go','.h','.hh','.hpp','.hxx','.inl','.java','.js','.jsx','.kt','.mjs','.py','.rs','.svelte','.ts','.tsx','.vue']` in `cli/lang/legacy-extensions.js`; `PRE_PHP_EXCLUDED` and the live derivation go. `currentLanguages()` lists only extensions whose record has audit stage `on`, so dark records never enter a scope's recorded languages.
2. **Baseline snapshot** (P0-1). A scope gains `byExtension: { '.py': { RULE: n } }`, written by `writeRatchet` and by every `upgradeScope` that already rewrites the file (adoptions, ruleset bumps), never causing a rewrite by itself. It is the per-extension split of the counts that became the baseline.
3. **Analysis adoption** (P4-5). A scope records `analysis: { ext: analysisId }`, where `analysisId = '${engine}:${id}@${audit.analysisRevision}'` with `engine` the effective audit engine (`text` when grammars are unavailable or the stage is below `on`), and `legacy` for every analyzer unchanged since the freeze. A scope without `analysis` reads `legacy` for every recorded extension. When the current id for extension E differs and is not a downgrade (current engine `text`), only engine-specific rules adopt: the adoptable set is the rules emitted by non-text passes of the current or recorded analyzer. Universal text rules (TYPOGRAPHY_EM_DASH, SECURITY_HARDCODED_SECRET, ...) are never adopted this way, because their E hits are already in the baseline. With a snapshot, `rules[R] = rules[R] - byExtension[E][R] + current[E][R]` and the snapshot is updated. Without one, only rules the recorded analyzer could not emit for E adopt (`rules[R] += current[E][R]`, exact because the baseline holds no E hits for them); shared rules stay gated and the scan says the scope needs a re-recorded baseline. Downgrades are not recorded, so uninstalling and reinstalling grammars cannot launder findings. A scan that adopts prints `adopted: <ext> (<old> -> <new>)`. Trade-off, as with rule revisions: a real regression in E in an engine-specific rule during the adopting scan is adopted too, so analysis bumps land in their own commits.

### 4.14 Framework plugin layer

`cli/frameworks/<id>.js` records sit on top of host languages: `vue`, `svelte`, `react`, `capsules` (atomic-design tiers, controller/view contract, co-located tests) and `wordpress` (points at the existing `cli/php/wp-detect.js`, its passes and project index). ### 4.15 N/A capabilities

`cli/lang/capabilities.js` `requireCapability(path, feature)` returns `{ ok }` or `{ refusal: '<feature>: not supported for <Language> (<reason>)' }`. Called by `explode-plan.js`, `mutators.js` (`add:prop`, `add:state`), `generator.js`, `scaffold.js`, `forge/file-units.js` and `library/verify.js`. `project-detector.resolveFramework` no longer defaults to react when no npm ecosystem owns the target. Forge, heal, explode, generate, capsule, scaffold, lanes, template and autofix fences are N/A for every non-JS record; text autofix (residue and truncation) applies wherever record comment syntax is known.

### 4.16 Adding language 26, and extending a vocabulary

A new language that fits the existing vocabularies costs: one `grammars.lock.json` entry and a rebuild, one record, query files, one fixture module (`cli/fixtures/lang/<id>.fixtures.js`), one golden spec (`cli/lang/specs/<id>.slow.spec.js`), optionally a precision file and an ecosystem record with captured fixtures, then stage flips one commit each.

Every closed vocabulary has exactly one registration point in `cli/lang/vocab.js` (filled by P0-4), the source of truth for vocabulary members: symbol kinds, captures, engines, resolver names, export rule kinds, target modes, workspace formats, manifest formats, parser ids and the hook families (region, import normalizer, implicit-edge, analyzer, planner, format). This spec does not enumerate members; `ANALYZER_HOOKS` starts empty. Code behind a name is a module found by convention (`cli/lang/hooks/<name>.js`, `cli/resolve/<name>.js`, `cli/resolve/implicit/<name>.js`, `cli/toolchain/parsers/<id>.js`, `cli/toolchain/formats/<name>.js`, `cli/toolchain/hooks/<name>.js`), loaded by dynamic import after a name check, so no index file becomes a hot spot. `cli/lang/vocab-wiring.spec.js` asserts that every vocabulary entry has its module, every module is registered, and every consumer switch (template expansion, workspace readers, manifest readers) handles every entry. A language with a novel module system therefore costs one hook module, one vocabulary line and its spec.

## 8. Testing

- **Fixtures are JS modules**, never source files on disk: `cli/fixtures/lang/<id>.fixtures.js` holds real-shaped code strings and expected rows, outline lines, comment regions and logic skeletons (the PHP precedent; `cli/fixtures/**` is unpublished). They cover the defects the maps found: Python docstring and comment phantoms, decorated defs, constants; Go receiver methods and grouped imports; Rust impl, trait, `macro_rules!`, use-trees and `mod` declarations; Java and C# constructors and expression-bodied members; Kotlin `suspend fun` and `object`; C typedefs; C++ out-of-line methods and namespaces; a non-ASCII line for column units.
- **Grammar-dependent specs** are named `*.slow.spec.js` (slow lane by convention) and call `t.skip('grammars not built: node grammars/scripts/build.mjs')` when grammars are absent, which shows in the counts. CI sets `CHEMX_REQUIRE_GRAMMARS=1`, turning that skip into a failure. One default-lane spec always runs without grammars and asserts the `grammars-not-installed` degrade.
- **Toolchain fixtures** are captured verbatim from real runs in digest-pinned images (python, golang, rust, maven, gradle, dotnet sdk, ruby, swift, dart) with tool version and command recorded. Nothing is hand-typed. Tools that cannot run here (MATLAB without a licence, `xcodebuild` on Linux) keep their ecosystem stage `off` with a named reason.
- **Spec globs.** P0-2 adds every new spec directory to `package.json` `test` at once: `cli/lang/*.spec.js cli/lang/specs/*.spec.js cli/lang/fallback/*.spec.js cli/lang/parity/*.spec.js cli/treesitter/*.spec.js cli/resolve/*.spec.js cli/frameworks/*.spec.js cli/toolchain/*.spec.js cli/toolchain/ecosystems/*.spec.js cli/toolchain/formats/*.spec.js cli/toolchain/manifest/*.spec.js grammars/scripts/*.spec.js`.

## 9. Team coordination

- All agents work on `main` in one checkout, split by file. Every task lists files, never directories; a new file is leased with `chemx team lock acquire <file> --new`. No two tasks in the same phase share a file; tasks in different phases that touch the same file are ordered by `dependsOn`.
- Hot files each have one owner per phase: `package.json` (P0-2, then P9-3), `cli/languages.js` (P0-6), `cli/audit/ratchet.js` (P0-1, P4-5), `cli/search-ast.js` (P3-2, P4-6), `cli/reader.js` (P3-3), `cli/audit/rules.js` (P4-1), `cli/verify.js` (P5-4, P7-3), `cli/test-output.js` (P5-3), `cli/hooks/guard-paths.js` (P1-11, P8-1), `cli/lang/records/index.js` (P0-5, P1-12), `cli/toolchain/ecosystems/index.js` (P5-2), `cli/commands/cmd-router.js` (P1-9), `cli/config/index.js` (P0-7), `README.md` (P8-5).

## 10. Risks

1. **Bridge viability.** Atomics-based synchronous calls into a worker are unusual. The spike confirmed it (section 4.6); plan B stays specified as the fallback, including its boundary list.
2. **Event-loop blocking.** A bridge call blocks its thread for up to one file's budget; an in-process MCP read of a pathological file stalls the server for up to 2 s. Heavy MCP actions stay offloaded; the per-file budget is configurable.
3. **WASM memory.** Grammars are never unloaded and linear memory never shrinks. The `external` memory cap and recycle bound it; recycling costs a recompile of large grammars.
4. **Grammar lag and dialects.** Newer syntax (Python 3.13+, C# 13, Kotlin 2.x, Swift macros), zsh in the bash grammar, T-SQL and PL/SQL produce ERROR nodes on valid code. `coverage-only` error policy, count-based gating, the shadow-first edit gate and SYNTAX_PARSE_ERROR off contain it.
5. **Supply chain.** Generate-from-source (SQL, Swift, Perl) and the compiler run third-party code at build time inside a builder container. Commit pins, archive sha256, an allowlist and denylist, a checksum-verified CLI, sha256-pinned wasi-sdk and binaryen assets, a digest-pinned image run with `--network none`, CI-built manifests with provenance and the kit-side sha lock mitigate it; npm install of grammar packages is never used.
6. **Ratchet trade-off.** Analysis adoption accepts engine-specific regressions in the adopting scan for that extension. Analysis bumps ship in their own commits and the scan prints what it adopted.
7. **Index transition churn.** Rows written by older chemx carry a NULL fingerprint and are re-parsed, so mixed versions cause extra parsing but never wipes. Real parsers change symbol and import counts, which shifts hotspot, clone and similarity features; flips go one language family per commit.
8. **Stale resolution.** Package and namespace languages depend on other files. The deferred post-pass must re-resolve on file-set changes; unresolved-local is reported, never counted as resolved.
9. **Polyglot ownership.** Several markers in one directory (package.json plus pyproject.toml) give several owners; verify runs all of them in that directory and lists nested foreign projects without running them, which may surprise users who expect everything to run.
10. **Guard tightening.** A guarded language whose outline is poor would leave agents only line-range reads. Guard flips require the conditions in section 4.13 and ship one family at a time.
11. **Toolchain output drift.** Formats change across tool versions. Machine formats are preferred, fixtures record versions, and unparsed output stays INCONCLUSIVE, never PASS.
12. **Precision without corpora.** Languages absent from the monorepo cannot reach default-on rules without third-party corpora (section 12); until then their rules stay in shadow.
13. **Grammar build toolchain and machine load.** The spike verified the build (spike note section 1): `tree-sitter build --wasm` 0.27.1 uses pinned wasi-sdk and binaryen with no container of its own, and python, go, sql and perl built in 84 s at a 679 MB peak with byte-identical output. About ten agents running `chemx verify`, Docker builds and fixture captures on one machine lengthen every commit cycle; grammar-dependent specs live in the slow lane and the default lane has a time budget.
14. **Language-id change.** Splitting `jvm` and `cpp` changes coverage buckets once (P4-1); external consumers of coverage JSON see a one-time change.
