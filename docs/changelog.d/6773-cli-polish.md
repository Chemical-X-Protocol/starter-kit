### CLI polish: zsh unsplit-argument hint, conflict markers in patch, q header cap, write reads piped stdin (#6773)

Reference: [commit.md](../commit.md), [search.md](../search.md#scoping-to-paths). Reported (K20, epic #6745): three or more agents hit each of these on 2026-10-25.

- zsh does not word-split an unquoted `$files`, so `chemx commit $files`, `chemx check $files` and `chemx test $specs` each received ONE argument, "a.js b.js", and answered with a message that blamed the files (`not tracked and not on disk`, `File not found`, `target(s) matched nothing`). One shared check (`cli/args-unsplit-hint.js`: an argument with spaces between words that is not a path on disk) now appends `one argument contains spaces: did a zsh variable not split? use an array or ${=var}` to those three messages, once. A real file with a space in its name is never flagged.
- `chemx patch` SEARCH text that holds merge-conflict lines no longer corrupts the file. The first `=======` used to end the SEARCH text, so a block that quoted a whole conflict region matched its first half and wrote the rest into the file. Every divider line in a block is now a candidate and the file decides: the split whose SEARCH text occurs in it, the longest first; a block with one divider, a REPLACE that writes a conflict region into a clean file, and the 8-character fence behave as before. A block that matches under no split fails with the usual "Block N of M: Target content not found".
- `chemx q -g` prints at most five scoped paths in its header and counts the rest (`in cli/a.js,...,cli/e.js (+493 more)`), so a shell-expanded glob no longer prints 498 names on every call. `--json` keeps the full `scope`.
- `chemx write <file> <<'EOF'` needs no `-` or `--stdin`: with no `--content`, `--content-file` or `-`, a piped, socket or redirected stdin is the content. An empty or idle stdin (`/dev/null`, an empty pipe, a harness's silent socket) still refuses and creates nothing; `--stdin` and `-` keep working, including for an empty file. `hasPipedStdin()` lives in `cli/terminal.js` beside the other tty helpers.
- Pinned by `args-unsplit-hint.spec.js` (8), `commit-unsplit.spec.js` (3), `cmd-check.spec.js` (+2), `test-unsplit.spec.js` (3), `search-literal-header.spec.js` (4), `patch-conflict-markers.spec.js` (8) and `write-stdin.spec.js` (8). No command, flag or action is new, so `identity-classification.js` is unchanged.
