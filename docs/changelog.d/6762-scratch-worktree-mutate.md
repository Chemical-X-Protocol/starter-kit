### Scratch space per agent, a worktree helper and a mutate-and-restore check (epic #6745, K17 #6762)

Full reference: [agent-workspace.md](agent-workspace.md). Reported by the agents of epic #1552 and the K12 agent: a shared scratchpad let one agent's `one.mjs` replace another's (an `ERR_MODULE_NOT_FOUND` three calls later); the Bash tool aliases `cp` to interactive, so two agents' restores after a mutation check silently did nothing; and every agent made its worktree and its `node_modules` by hand (K12 had to build a real directory of symlinks because a symlink to the main checkout cannot host a new devDependency).

- `chemx scratch [name]` prints, and creates when missing, `.chemx/scratch/<handle>/` of the project (a linked worktree has its own); with a name, the absolute path of that file inside it (folders are made, the file is not; a name that leaves the directory is exit 2). The handle is `--as`, then `CHEMX_AGENT_ID`, then the session handle, without the `@`; with none the directory is `_shared` and stderr says so. The directory is git-ignored: `git check-ignore` decides, and a `.gitignore` that lists only part of `.chemx` gets a `.chemx/scratch/` line (this repo's `.gitignore` lists it too).
- `chemx worktree add <path> -b <branch> [--from <ref>] [--link-modules] [--install]` runs `git worktree add -b`, from the remote default branch unless `--from` says otherwise, then gives the worktree `node_modules`: `--link-modules` makes a real directory of symlinks into the main checkout's (two levels for `@scope/name`, bookkeeping files left out), so an install in the worktree never writes into the main checkout; `--install` runs the package manager the lockfile names; both together link, then install what is missing. Output: the path first, the base commit, the `node_modules` line, and one line saying board commands run from the main checkout or with `--board`. A failed add leaves no branch behind.
- `chemx worktree remove <path> [--force]` removes the worktree and deletes its local branch when it is merged into the default branch, squash merges included (the branch is an ancestor of the base, or `git merge-tree --write-tree` shows merging it would change nothing); an unmerged branch, the main checkout, an unknown path and the directory you stand in are refused (exit 1), a dirty worktree is refused by git, and `--force` overrides the merge and dirty checks.
- `chemx mutate <file> --apply <diff-file|s/old/new/[g]> [--apply ...] --then "<command>" [--keep]` changes the file, runs the command as `chemx run` does (your terminal, your leases renewed), always restores the original bytes and modification time, reads them back, and exits with the command's code. The original is copied to `.chemx/scratch/<handle>/mutate/` first and deleted after a verified restore unless `--keep`. `--apply` is a unified-diff file for the one file (hunks must match, at most 40 lines off) or a per-line sed substitution with an optional line address (a JavaScript regular expression; `&`, `\1`..`\9` in the replacement). Exit 125 is chemx stopping: bad input, a binary file, a patch that does not apply, a change that changes nothing, a file another handle has leased, or a restore that did not verify (the copy is kept and named).
- The three are in the command schema (help, `--help`, flag checks, the guard's command probe), the AGENTS.md reflex table, the tesseract briefing (`chemx tesseract`) and docs/INDEX.md.
- Not changed: the guard rules (K11), team task files (K14), identity defaults (K16), `chemx read` (K7). Not covered: a chemx killed with SIGKILL during `mutate` cannot restore (the printed copy path is the way back); `worktree add` does not fetch.
