### Team help text split per subcommand (epic #6745, K18 #6767)

Every wave 1 pull request edited `cli/team/team-format.js` (one text for the three team help cards) and the `team` entry in `cli/commands-schema-ops.js`, and conflicted on rebase. Output is unchanged, byte for byte, colours included.

- Each team subcommand's help is its own small module in `cli/team/help/<subcommand>.js`: `teamCardRows`, its row (or rows) on the `chemx team --help` card. `task` has three modules for its card (`task.js` the row and the head, `task-actions.js` the Actions rows, `task-options.js` the Options rows) and `lock.js` holds the whole `chemx team lock --help` card.
- `cli/team/team-format.js` only assembles the three cards from them (`formatTeamHelpCard`, `formatTaskHelpCard`, `formatLockHelpCard`), the team card in the order of `help/card-rows.js`. A new row, action or option is a one-line edit in the module of its subcommand; only a new subcommand module needs an entry in `card-rows.js`.
- The `team` schema entry moved out of `commands-schema-ops.js` to its own `cli/commands-schema-team.js`, whose flags and examples are one array per subcommand (`FEED_FLAGS`, `TASK_SHOW_FLAGS`, `STATUS_FLAGS`, ...) put in help order by two lists, so two tickets on different subcommands edit different arrays. It is one file rather than one module per subcommand because the schema loads on every chemx command and each module costs about 1.4 ms of start-up (measured: 9 modules added 12 ms to `import commands-schema.js`); the help cards are only loaded by `team`.
- Pinned by `cli/team/team-help-golden.spec.js` against `cli/team/team-help-golden.json`: the three cards, the `team` schema entry and the `chemx help team` text, captured before the split. A deliberate help change refreshes the fixture with `UPDATE_GOLDEN=1 chemx test cli/team/team-help-golden.spec.js`.
