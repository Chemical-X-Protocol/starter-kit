### The generated protocol text names `wait --job` and the new commands, and a spec keeps it current (epic #6745, K23 #6776)

K9c added `chemx wait --job=<pid>` and `--post-matching`, and K13 to K18 added `run`, `ci`, `worktree`, `scratch`, `mutate`, `changelog` and `task add --from`, but the text every host reads (the protocol block in AGENTS.md and `.cursorrules`, `GEMINI.md`, `.agent/rules/chemx-protocol.md`, the dispatch WAITING line, the tesseract briefing) still listed `chemx wait` with `--task`, `--lock-free` and `--verify-idle`. The kit's own generated copies had also drifted from `cli/host-protocol.js` by hand edits (#6756 and an older slice-read edit); regenerating with `chemx pillars --protocol-only --write` folded both into the generator.

- `cli/host-protocol.js`: the Wait step lists all five modes (`--task`, `--lock-free`, `--verify-idle`, `--job=<pid>`, `--post-matching=<text> [--from=@<handle>]`) and `--timeout`. Claim names `chemx task` (the short form of `chemx team task`), `task show --brief`, `task add --from` and `team brief`; Lock says several paths go in one call; Edit says `chemx read <path>:N-M --bare` (only the range form that exists today; `--lines` and `--full` wait for K7); Commit names `--board=<dir>` and `--no-skip-ci`. Two steps are new: Workspace (`scratch`, `worktree add|remove`, `mutate`, `run --`) and Pull request (`ci --wait`, `ci --protection`, `docs/changelog.d/<ticket>.md`, `changelog`). The protocol now has 15 steps (the Wait step is 10), and a raw `git worktree` is replaced by `chemx worktree` in the Commit step.
- `cli/team/team-dispatch-prompts.js`: the WAITING line of every build, review and repair prompt names all five modes; `cli/fixtures/dispatch/workflow-golden.txt` was rewritten by the spec's own writer (`CHEMX_UPDATE_GOLDEN=1`), and only that sentence changed (15 prompts).
- `cli/lattice-directives.js`: the tesseract briefing gains `run`, both `wait` lines, `task add --from`, `commit --board/--no-skip-ci`, `ci --wait` and `changelog --check`.
- New `cli/host-protocol-coverage.spec.js`: derives the command list from `cli/commands-schema*.js` and the wait modes from `cli/wait-command.js` (and checks the wait schema entry agrees), then asserts every command not in its `EXCLUDED` array (a reason each) is named as `chemx <name>` in the protocol block, `GEMINI.md` and the Antigravity rule; that the dispatch WAITING line and the tesseract briefing name every wait mode; and that the kit's own AGENTS.md block, `.cursorrules` block, `GEMINI.md` and `.agent/rules/chemx-protocol.md` equal what the generator writes. A new schema command or wait mode fails it until the text names it or `EXCLUDED` says why not. `host-protocol.spec.js` pins 19 more phrases.
- AGENTS.md reflex table: a row for `chemx test ... & chemx wait --job=$!`. `docs/team-dispatch.md` states the new WAITING line.
- Not changed: the test selector (K9d), lease specs (K22), index and worktree code, `chemx read` (K7). Not guaranteed: an agent that ignores its rules file is still not stopped; only the Claude Code hooks block a call.
