### Status in a linked worktree, worktree remove and the branch it was cut from (epic #6745, K24 #6777)

Four agents (K12, K8b, K17, K21) reported `chemx status` labelling every changed file in a private worktree `[unleased: someone may be mid-edit]`, which is noise where no other handle can edit; and `chemx worktree remove` judged "merged" against `origin/HEAD` only, so a branch cut `--from` a local branch ahead of origin needed `--force`. Reference: [team-locks.md](team-locks.md), [agent-workspace.md](agent-workspace.md).

- `chemx status` inside a linked git worktree no longer prints the unleased hint, `flagged` is `false` for an unleased file, and the counts line reads `N unleased (linked worktree: not flagged)`. A live lease by another handle is still shown and flagged. The main checkout is unchanged. Detection is git's own (`isLinkedWorktree` in `cli/worktree-git.js`: the worktree's git dir, reached through the `.git` gitdir pointer, differs from the common git dir), not a path heuristic. `--json` gains `linkedWorktree` (#6777).
- `chemx worktree add` records the branch it cut from (the `--from` value or the resolved default; `HEAD` becomes its branch name) in `chemx-worktree.json` in the worktree's own git dir (`<main>/.git/worktrees/<name>/`): never in the working tree or `git status`, deleted with the worktree.
- `chemx worktree remove` treats the branch as merged when it is an ancestor of, or squash-merged into, either the default branch (judged first) or the recorded base, and prints which (`squash-merged into main`). The refusal names both (`not merged into origin/main or main`), and says when the recorded base no longer exists or its record is unreadable. A worktree with no record, or switched to another branch, is judged against the default branch only, as before (#6777).
- Not changed: the lease views, the board, `--force` (still overrides the merge check and the dirty check).
