### Fixed

- Catch-family escalation (truth spec 4.2): an `&&` chain or an `if`/conditional test guards a read only with a link that rules out an unset binding (`v`, `!!v`, `v != null`, `v !== undefined`, `typeof v !== 'undefined'`), and an alternate only with an unset check. `a && !v && v.x` and `if (a && !v) use(v.x)` are HIGH again, and so is `if (!v) use(v.x)` (#253).
- A write of the binding before the try, or after it and before the read, is a default as on main, except in two shapes where a path provably reaches a read in the try's function without it, which report HIGH. One is a write in a function nothing calls (a declaration directly in a function body or the module, or a variable's initialiser, that is not exported and is referenced only from inside itself, but not one declared in an inner block or a `case`, which sloppy code can call from outside it), or in a callback passed straight to `setTimeout`, `setInterval`, `setImmediate`, `queueMicrotask`, `requestAnimationFrame`, `process.nextTick`, `addEventListener`, `on` or `once` by a call that is the whole of its statement (`setTimeout(cb);` or `const id = setTimeout(cb);`, but not `await queueMicrotask(cb);` or `em.on('x', cb).emit('x');`). The other is a write that runs only while the binding is set (`if (v) v = v.trim()`, `if (v != null)`, `v && (v = d)`, the `else` of `if (!v)`). A deferred callback and a set-only write are proven skips only in the simple position: the deferring call's statement, the `if` or the `&&` or `||` statement is a statement of the block that holds the read, in the try's function; it holds no try itself and has no loop or label around it inside the binding's scope; nothing between it and the read returns, breaks, continues, throws, awaits or yields; and no function that may still be called writes the binding after the read (a helper declared at the end). A deferred callback also needs no call in between (`jest.runAllTimers()`, `emitter.emit('x')`, or a `v = f()` in a try that comes between), and for a set-only write the read must run whenever its statement does (`c ? v.x : 0` after `if (v) v = v.trim()` keeps MEDIUM). No proof applies once a write before the read sits in another swallowed try, which main never counts even when it always runs (`try { try { g(); } finally { v = d; } } catch {}`). Every other shape keeps main's MEDIUM: a write under an `if` with no `else`, whatever its test (`if (cond) v = d;`, `const missing = !v; if (missing) v = {};`), a callback passed to a promise's `then`, `catch` or `finally` (an `await` on the promise runs it first), the `else` of another test, a ternary, `ok && (v = d)`, a loop body or head (`for (v of xs)`), a `switch` case, a catch, a label, an immediately invoked function in any form, an async or generator body, and a closure passed to any other call (#253).
- `chemx-allow` block comments: an annotation on a comment-only line covers the rest of its own comment, a closer line that code shares (`*/ try { ... } catch (e: any) { ... }`) and the line below its closer, for every rule, as on main before #257. That includes a ` * chemx-allow:` continuation line of a block that opened after code on an earlier line (`doThing(); /* ...`), which main tested by its own line too. For the catch family, a comment-only marker line right above the catch's line counts as on main whatever line opened its block, and a block whose closer is on the line above the catch or on the catch's line before its keyword counts when the block opened on a comment-only line. PHP block annotations with the reason on the marker line now last to their closer as JS and TS ones do (#253).
- `chemx-allow` for rules outside the catch family reads as on main again where #257 was stricter: when two markers share a line and the first has no reason of its own (`// chemx-allow: TYPOGRAPHY_EM_DASH chemx-allow: UNGUARDED_LOGGING quoting`), the rest of the line is its reason, and a reasonless marker takes its reason from a block comment still open at the end of its line even when that is another comment (`/* chemx-allow: TYPOGRAPHY_EM_DASH */ x(); /* still` ... `reason */`). These rules have no revision, so their counts cannot rise over main's. The catch family keeps reading each marker alone, as its revisions record (#253).
- Catch annotation ownership by column (#257) applies only where two try statements meet: when the catch's line or its last line holds a `try` or `catch` keyword other than its own and its try's. Every other catch reads its annotations by line as on main (its own lines, a comment-only marker line right above it, the text after its try brace), plus the block-comment window above. So neither a `try` or `catch` that is not a keyword (a string or template literal, a member such as `p.catch(h)`, an object or type key, a method, a `$`, `#` or `@` name, a regex literal, JSX text) nor code the comment scanner reads as a comment (a private member such as `#x = 1` or `#brand in o`, a regex holding `//` or `/*` such as `/^https?:\/\//` or `/\/*$/`, JSX text such as `<h2>Item #1</h2>` or `<a>http://x</a>`) changes what such a catch owns. Where two tries do share a line, ownership reads the keywords themselves (the parser's try statements and catch clauses for JS, TS, JSX and Vue; for C#, a whole word in code with comments and strings blanked, no `.` or `@` before it, followed by a block, or for `catch` by a type or a `when` filter), and for JS, TS, JSX and Vue the annotation's comment as the parser reads it, so a misread comment cannot move it there either. C# keeps the line scanner for comments. The C# masker now reads an interpolated string (`$"..."`, `$@"..."`, `@$"..."`, raw `$"""..."""`) as text and holes: it blanks the text, each hole's braces and format, and the strings, chars and comments in a hole's code, and keeps the rest of that code, while a raw `"""..."""` without `$` is blanked whole. So a quote, a brace or try or catch text in a string inside a hole (`$"{(c ? "try {" : "catch (")}"`) is neither a keyword nor the end of the string, a try/catch in a lambda inside a hole is found as on main, and method complexity and nesting still read no hole code (#253).
- Precision change from main: a try whose block holds a plain write of the binding as one of its statements (`v = g2();`, `v ??= d;`) and whose catch holds an exit statement (`catch { return; }`, `break`, `continue` or `throw`), or whose finally holds such a write, guards the reads in the later statements of its block, outside nested functions. So `let v; try { v = g2(); } catch { return; } use(v.x);`, a `catch { break; }` or `catch { continue; }` before a read later in the loop body, `try { v = f(); } catch {} finally { v = d; }`, and an earlier swallowed try followed by such a one (`try { v = f(); } catch {} try { v = g2(); } catch (e) { return; } return v.x;`) are MEDIUM where main reported HIGH. A try nested in a loop, a label or another block that ends before the read (`for (const x of xs) { try { v = g2(); } catch { break; } }`, `while (true) { try { v = f(); break; } catch { continue; } }`, `if (k) { try { v = g2(); } catch { return; } } use(v.x);`), one that writes only under a branch (`try { if (c) v = f(); } catch { return; }`) or inside an expression (`try { set(v = g2()); } catch { return; }`), and one whose catch exits only under a branch (`catch { if (k) return; }`) keep main's HIGH. Counts do not change (#253).
- C# shallow catches report the catch keyword's column instead of 1, so two on one line are two findings and annotation ownership by column changes the count. A catch at the start of its line reports column 1, as the JS catch rules do, so the reporter keeps the column. This folds into the ruleset 13 revision of `AI_SLOP_SHALLOW_CATCH` (#253).
