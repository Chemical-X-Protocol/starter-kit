### Fixed

- Catch-family escalation (truth spec 4.2): an `&&` chain or an `if`/conditional test guards a read only with a link that rules out an unset binding (`v`, `!!v`, `v != null`, `v !== undefined`, `typeof v !== 'undefined'`), and an alternate only with an unset check. `a && !v && v.x` and `if (a && !v) use(v.x)` are HIGH again, and so is `if (!v) use(v.x)` (#253).
- A write is a default when the `if`/`else`, conditional, switch with a `default`, or immediately invoked function around it writes on every path, so `if (c) v = 1; else v = 2;` stays MEDIUM. A write that runs only while the binding is set (`if (v) v = v.trim()`, the `else` of `if (!v)`) and a `for (v of xs)` or `for (v in o)` head no longer count as one for reads after the loop, so those reads are HIGH (#253).
- A path that leaves instead of writing is no unwritten path when it skips the read: `if (c) v = 1; else return;`, `else throw ...`, a `default:` that throws, and a `break` or `continue` out of a loop that holds the read keep the catch MEDIUM. A `return` in a nested function, or a `break` aimed at a loop inside the branch, is not an exit of the branch. An exit the read can still follow stays unwritten, so these stay HIGH: a `return` out of an invoked function, a `break` out of a labeled block, a `while (!v)` loop or a `do`/`while` loop that ends before the read, a `throw` into a `catch`, and a `return` through a `finally` that reads the binding (#253).
- `chemx-allow` block comments: an annotation on a comment-only line covers the rest of its own comment, a closer line that code shares (`*/ try { ... } catch (e: any) { ... }`) and the line below its closer, for every rule, as on main before #257. That includes a ` * chemx-allow:` continuation line of a block that opened after code on an earlier line (`doThing(); /* ...`), which main tested by its own line too; only catch ownership asks where the block opened. A catch-family annotation whose block opens on a comment-only line and closes before the catch keyword on the catch's line owns that catch. PHP block annotations with the reason on the marker line now last to their closer as JS and TS ones do (#253).
- `chemx-allow` for rules outside the catch family reads as on main again where #257 was stricter: when two markers share a line and the first has no reason of its own (`// chemx-allow: TYPOGRAPHY_EM_DASH chemx-allow: UNGUARDED_LOGGING quoting`), the rest of the line is its reason, and a reasonless marker takes its reason from a block comment still open at the end of its line even when that is another comment (`/* chemx-allow: TYPOGRAPHY_EM_DASH */ x(); /* still` ... `reason */`). These rules have no revision, so their counts cannot rise over main's. The catch family keeps reading each marker alone, as its revisions record (#253).
- A catch annotation above a one-line try, before the catch keyword on its line, or trailing a C# catch, is no longer taken away by a `try` or `catch` that is not a keyword: text in a string or template literal (`log('try')`, `a('catch')`), a member (`p.catch(h)`, `p?.catch(h)`), an object or type key (`{ catch: h }`, `{ try: 1 }`, `type P = { catch: () => void }`), a method (`catch() {}`), a `$`, `#` or `@` name (`$catch`, `try$`, `this.#catch()`, C# `var @catch`), a regex literal (`/try/`, `/catch/g`) or JSX text (`<p>try</p>`). Ownership reads the keywords themselves: the parser's try statements and catch clauses for JS, TS, JSX and Vue, and for C# a whole word in code (comments and strings blanked) with no `.` or `@` before it, followed by a block, or for `catch` by a type or a `when` filter. The C# limit of a trailing annotation (a later try, the brace of an enclosing try part) reads keywords the same way. Only a real second try or catch between them ends the annotation's ownership (#253).
- Escalation counts more paths as written: a loop that always runs its body (`while (true)`, `while (1)`, `for (;;)`, a `do`/`while`) and writes before its break, a `try` whose `catch` rethrows (`if (c) { try { v = g2(); } catch (e) { throw e; } } else { v = 2; }`), a `try` whose `finally` writes, a labeled loop, and a `throw` in a branch of an immediately invoked function, which leaves through the call and skips the read. These keep the catch MEDIUM as on main. A loop that may not run, a break before the write, a throw caught before the read, and an async IIFE that awaits before the write stay HIGH (#253).
- Escalation also looks past the first branch around a write and reads more invocation forms, so these keep the catch MEDIUM as on main: a write and `break` under an `if` in a loop that always runs (`for (;;) { if (c) { v = 1; break; } }`, the same in `while (true)` or inside an IIFE), a loop test Babel evaluates to a truthy constant (`while (!0)`, `while (-1)`, `while ('x')`), a function expression run through `.call`, `.apply`, `?.()` or a bound copy (`(function () { v = 1; }).call(this)`, `(function () { v = 1; }).bind(this)()`) or constructed with `new (function () { v = 1; })()`, an async IIFE that writes before its first `await` (`(async () => { v = 1; })();`, which runs that far at the call), and a write in a `try` whose swallowing `catch` always leaves past the read (`if (c) { try { v = g2(); } catch { return; } } else v = 2;`). An `await` before the write (`(async () => { v = await g2(); })()`), a generator, a bound copy that is never called, a loop that may not run (`while (k)`, `while (0)`) and a `catch` that can fall through to the read stay HIGH (#253).
- Precision change from main: a swallowed catch whose own `try` writes the binding on every path that goes on to the read is MEDIUM where main reported HIGH, because the swallowed error never reaches the read: `let v; try { v = g2(); } catch { return; } use(v.x);`, a `catch { break; }` or `catch { continue; }` that skips a read later in the loop, and a `finally` that writes (`try { v = f(); } catch {} finally { v = d; }`). An earlier swallowed try whose binding such a try writes is MEDIUM too (`try { v = f(); } catch {} try { v = g2(); } catch (e) { return; } return v.x;`); inside a branch main already reported both catches MEDIUM. Counts do not change (#253).
- C# shallow catches report the catch keyword's column instead of 1, so two on one line are two findings and annotation ownership by column changes the count. A catch at the start of its line reports column 1, as the JS catch rules do, so the reporter keeps the column. This folds into the ruleset 13 revision of `AI_SLOP_SHALLOW_CATCH` (#253).
