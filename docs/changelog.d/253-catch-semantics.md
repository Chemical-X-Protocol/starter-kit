### Fixed

- Catch-family escalation (truth spec 4.2): an `&&` chain or an `if`/conditional test guards a read only with a link that rules out an unset binding (`v`, `!!v`, `v != null`, `v !== undefined`, `typeof v !== 'undefined'`), and an alternate only with an unset check. `a && !v && v.x` and `if (a && !v) use(v.x)` are HIGH again, and so is `if (!v) use(v.x)` (#253).
- A write is a default when the `if`/`else`, conditional, switch with a `default`, or immediately invoked function around it writes on every path, so `if (c) v = 1; else v = 2;` stays MEDIUM. A write that runs only while the binding is set (`if (v) v = v.trim()`, the `else` of `if (!v)`) and a `for (v of xs)` or `for (v in o)` head no longer count as one for reads after the loop, so those reads are HIGH (#253).
- `chemx-allow` block comments: a comment-only annotation covers the rest of its own comment, a closer line that code shares (`*/ try { ... } catch (e: any) { ... }`) and the line below its closer, for every rule, as on main before #257. A catch-family annotation whose block opens on a comment-only line and closes before the catch keyword on the catch's line owns that catch. PHP block annotations with the reason on the marker line now last to their closer as JS and TS ones do (#253).
- C# shallow catches report the catch keyword's column instead of 1, so two on one line are two findings and annotation ownership by column changes the count. This folds into the ruleset 13 revision of `AI_SLOP_SHALLOW_CATCH` (#253).
