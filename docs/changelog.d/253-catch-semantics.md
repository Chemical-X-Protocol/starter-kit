### Fixed

- Catch-family escalation (truth spec 4.2): an `&&` chain or an `if`/conditional test guards a read only with a link that rules out an unset binding (`v`, `!!v`, `v != null`, `v !== undefined`, `typeof v !== 'undefined'`), and an alternate only with an unset check. `a && !v && v.x` and `if (a && !v) use(v.x)` are HIGH again, and so is `if (!v) use(v.x)` (#253).
- A write of the binding before the try, or after it and before the read, is a default as on main, except in three shapes where a path provably reaches the read without it, which report HIGH: a write in a function nothing calls, or in a callback passed straight to `setTimeout`, `setInterval`, `setImmediate`, `queueMicrotask`, `requestAnimationFrame`, `process.nextTick`, `addEventListener`, `on`, `once` or a promise's `then`, `catch` or `finally`; a write under an `if` with no `else` whose test may fail (`if (cond) v = d;`, but not `if (true)`, `if (true as boolean)` or `if (1n)`); and a write that runs only while the binding is set (`if (v) v = v.trim()`, `if (v != null)`, `v && (v = d)`, the `else` of `if (!v)`). Each holds only in the simple position: the `if` (or the deferring call) is a statement of the block that holds the read, in the try's function, holds no try itself, has no loop or label around it inside the binding's scope, and nothing between it and the read returns, breaks, continues, throws, awaits or yields, and no function that may still be called writes the binding after the read (a helper declared at the end). A deferred callback also needs no call in between (`jest.runAllTimers()`, `emitter.emit('x')`); an `if` test needs its names to appear nowhere else in the function, so `if (!ok)` after `ok = true` in the try, `if (c) v = 1; if (!c) v = 2;` and `assert(c)` keep main's MEDIUM; and for an `if` the read must run whenever its statement does (`if (c) use(v.x)` or `c ? v.x : 0` after `if (c) v = 1` keep MEDIUM). Every other shape keeps main's MEDIUM: the `else` of another test, a ternary, `ok && (v = d)`, a loop body or head (`for (v of xs)`), a `switch` case, a catch, a label, an immediately invoked function in any form, an async or generator body, and a closure passed to any other call (#253).
- `chemx-allow` block comments: an annotation on a comment-only line covers the rest of its own comment, a closer line that code shares (`*/ try { ... } catch (e: any) { ... }`) and the line below its closer, for every rule, as on main before #257. That includes a ` * chemx-allow:` continuation line of a block that opened after code on an earlier line (`doThing(); /* ...`), which main tested by its own line too; only catch ownership asks where the block opened. A catch-family annotation whose block opens on a comment-only line and closes before the catch keyword on the catch's line owns that catch. PHP block annotations with the reason on the marker line now last to their closer as JS and TS ones do (#253).
- `chemx-allow` for rules outside the catch family reads as on main again where #257 was stricter: when two markers share a line and the first has no reason of its own (`// chemx-allow: TYPOGRAPHY_EM_DASH chemx-allow: UNGUARDED_LOGGING quoting`), the rest of the line is its reason, and a reasonless marker takes its reason from a block comment still open at the end of its line even when that is another comment (`/* chemx-allow: TYPOGRAPHY_EM_DASH */ x(); /* still` ... `reason */`). These rules have no revision, so their counts cannot rise over main's. The catch family keeps reading each marker alone, as its revisions record (#253).
- A catch annotation above a one-line try, before the catch keyword on its line, or trailing a C# catch, is no longer taken away by a `try` or `catch` that is not a keyword: text in a string or template literal (`log('try')`, `a('catch')`), a member (`p.catch(h)`, `p?.catch(h)`), an object or type key (`{ catch: h }`, `{ try: 1 }`, `type P = { catch: () => void }`), a method (`catch() {}`), a `$`, `#` or `@` name (`$catch`, `try$`, `this.#catch()`, C# `var @catch`), a regex literal (`/try/`, `/catch/g`) or JSX text (`<p>try</p>`). Ownership reads the keywords themselves: the parser's try statements and catch clauses for JS, TS, JSX and Vue, and for C# a whole word in code (comments and strings blanked) with no `.` or `@` before it, followed by a block, or for `catch` by a type or a `when` filter. The C# limit of a trailing annotation (a later try, the brace of an enclosing try part) reads keywords the same way. Only a real second try or catch between them ends the annotation's ownership (#253).
- Precision change from main: a try whose block holds a plain write of the binding as one of its statements and whose catch holds an exit statement (`catch { return; }`, `break`, `continue` or `throw`), or whose finally holds such a write, guards the reads in the later statements of its block. So `let v; try { v = g2(); } catch { return; } use(v.x);`, a `catch { break; }` or `catch { continue; }` before a read later in the loop body, `try { v = f(); } catch {} finally { v = d; }`, and an earlier swallowed try followed by such a one (`try { v = f(); } catch {} try { v = g2(); } catch (e) { return; } return v.x;`) are MEDIUM where main reported HIGH. A try nested in a loop, a label or another block before the read (`for (const x of xs) { try { v = g2(); } catch { break; } }`, `while (true) { try { v = f(); break; } catch { continue; } }`) or one that writes only under a branch (`try { if (c) v = f(); } catch { return; }`) keeps main's HIGH. Counts do not change (#253).
- C# shallow catches report the catch keyword's column instead of 1, so two on one line are two findings and annotation ownership by column changes the count. A catch at the start of its line reports column 1, as the JS catch rules do, so the reporter keeps the column. This folds into the ruleset 13 revision of `AI_SLOP_SHALLOW_CATCH` (#253).
