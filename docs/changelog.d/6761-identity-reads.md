### Identity: reads, gates and help need no handle (epic #6745, K16 #6761)

Full reference: [team-dispatch.md](team-dispatch.md#identity-which-calls-need-a-handle). Before, a dispatched builder's hook (`dispatch-identity`) refused every chemx call that named no identity, `chemx --help` and `chemx q` included, and a subagent's `inherited-identity` rule counted `test` and `verify` as acting; with no persistent shell each Bash call began with an `export CHEMX_AGENT_ID=...;`.

- One list decides it: `cli/team/identity-classification.js`. A **write** changes files or shared state (`write`, `patch`, `add`, `explode`, `generate`, `commit`, `run`, `heal`, `changelog`, setup commands, `project init`, `team task claim|done|handoff|comment|update|add|close|...`, `team lock acquire|release|renew|check` or a path alone, `team unlock|post|dm|inbox|dispatch|...`) and still needs `--as`, an inline `CHEMX_AGENT_ID=` or an earlier `export` in the same call, refused with the same text as before. A **read** (look and search, the gates `test`, `typecheck`, `lint`, `build`, `verify`, `audit`, `doctor`, `ci`, `team status|feed|tokens|route|audit-run`, `team task list|show`, `team lock status|list|check-staged`, help and version) runs with none and prints no identity line.
- Flags and words flip a call: `lint --fix`, `audit --triage|--triage-all|--rebaseline|--fix`, `doctor --fix`, `mcp --install`, `friction add|export`, `patterns reject` and `blueprint fill` are writes; `project status|learnings`, `hook claude-*` and `changelog --check|--dry-run` are reads; `--help` or `-h` before a `--` makes any call a read; `--root=<dir>` never changes the class; `chemx do "..." "..."` writes when any quoted call does.
- Also closed, since the same list now reads the router's own words: `team lock <path>` (a path alone is acquired), `team unlock` and `chemx --root=<dir> <write>` were never counted as acting for a subagent. Now classed as writes beyond the old set: `add`, `explode`, `heal`, `badge`, `run`, `changelog`, `init`, `create`, `pillars`, `install-mcp`, `hook` installs, `project init|step|chat`, `team inbox|triage|train|profile|handoff|dispatch|migrate|unlock`, `team lock check|renew`, `team task trace|slot|set-target|set-files|reconcile|triage`.
- A read with no `--as`, `CHEMX_AGENT_ID` or session id runs under a derived handle `@session-<id8>` (`resolveReadIdentity`, `isStableIdentity` in `agent-identity.js`) that holds nothing: `requestFileLock` and `claimTask` refuse the reserved `@session-` prefix (`derived_handle`), `registerAgent` registers no row for it and a feed event it would author reads as `@system`. A write keeps its four tiers and the per-process fallback.
- `audit-run` "subagent acted as orchestrator" uses the same list, so a gate or a help call is no longer listed; the generic MCP `team` action and `autofix` are read as the writes they are. A gate that names a handle still declares it for the native-edit guard (`declared-identity.js`).
- `identity-classification.spec.js` walks the command schema, its aliases and the team subcommand, task action and lock action trees, and fails until each is in exactly one list: a new command cannot go unclassified.
- Specs 52 -> 77 across `agent-identity`, `audit-run-identity`, `cli-usage`, `identity-classification` (new, 11), `derived-handle` (new, 5), `dispatch-identity`, `session-identity-subagent` and `declared-identity`. Not changed: the guard rules (K11), `chemx lint` (K12), team task files, `ci` and `tokens`, help-text layout, `read`.
- Not guaranteed: a command whose class depends on config (`audit` with `autoTriage: true`), an identity or subcommand held in a shell variable, and MCP calls (checked only after the fact by `audit-run`).
