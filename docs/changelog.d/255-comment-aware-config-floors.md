### Fixed

- `cli/main.js` (the audit's project config) and `cli/project-detector.js` (framework, `preset` and `dirs` for the generators) read `.chemx/config.json` through `cli/config/loader.js`, so a config with `//` or `/* */` comments no longer reads as `{}`. Before, a commented config silently dropped `minGrade`, `minScore`, `stage` and `model` from `chemx audit` (#255).
- Pre-commit grade gate (`CHEMX_PRECOMMIT_GATE=grade`): `scripts/pre-commit.sh` and the installed hook no longer grep `.chemx/config.json` for `minGrade`/`minScore`, a match that also took commented-out lines and nested keys. They run `audit --git` with their defaults exported as `CHEMX_DEFAULT_MIN_GRADE`/`CHEMX_DEFAULT_MIN_SCORE`, and `chemx audit` resolves the floors: the flag, then `CHEMX_MIN_GRADE`/`CHEMX_MIN_SCORE`, then the config, then the new low-precedence `--default-min-grade`/`--default-min-score` flags, then that env pair. The hooks use the env pair rather than the flags because an older chemx refuses an unknown audit flag, which would block every commit when a newer chemx renders the hook and an older local one runs it; an older chemx ignores the env pair (#255, #253). With `CHEMX_VERBOSE=1` the hook banner now names the gate and where its floors come from, instead of floors the hook no longer resolves (#255).
- `chemx audit` checks every floor value. A `--min-grade`, `--min-score` or `--default-min-*` value that is not `A+` to `F` (any case) or an integer from 0 to 100 is a usage error that names the flag and the value, and nothing is audited. Such a value in `CHEMX_MIN_GRADE` or `CHEMX_MIN_SCORE`, which the operator set, is the same usage error naming the variable and the value. Such a value in `CHEMX_DEFAULT_MIN_*` or the config is skipped with a one-line warning on stderr that names the source and the value, and the next source applies. A score with only zeros after the point counts as that integer, so `100.0` is `100`. Before, an unknown grade became a floor that never failed and still switched off the default gate, and a score was cut at its first non-digit, so `95.5` became `95`. A `minScore` of 0 in the config now counts as a floor, as it already did from the flag or the env (#255, #253).
- Behaviour change: `CHEMX_MIN_SCORE=98.5`, `+98` or `98abc` (and an unknown `CHEMX_MIN_GRADE`) now fails the audit, and the pre-commit grade gate, as a usage error. Before, `parseInt` enforced `98.5` as `98`; skipping the value instead would have left a CI audit with no floor at all, a weaker gate that still passed (#253).
