### Fixed

- `chemx-allow: best-effort` annotations take any separator after the token. The token ends at the first character that is not a letter, digit or underscore, and a hyphen that joins two words stays inside it, so `best-effort, x`, `best-effort. x`, `best-effort(x)`, `best-effort/x` and `best-effort-- x` are the annotation, with the separator dropped from the start of the reason. Before, these were not read as an annotation, and the catch was flagged with no "reason is mandatory" note. `best-effort-ish`, `best-effort_x` and `best-effort2` are still other tokens (#257).
- A rule id that holds a digit can now be annotated: `chemx-allow: A11Y_CLICKABLE_NON_SEMANTIC <reason>` and `chemx-allow: A11Y_IMAGE_MISSING_ALT <reason>` exempt their findings, and a reasonless one gets the "reason is mandatory" note. Main read a token as letters, `_` and `-` only, so these two rules ignored every annotation. Their counts can only fall, so neither has a new revision (#257).
- Catch-family annotations (`ERROR_SWALLOWED_EXCEPTION`, `AI_SLOP_SHALLOW_CATCH`) are owned by column, not by line, where the catch's first or last line holds the `try` or `catch` keyword of another try statement with a catch, or in C# of another catch of the same try (#253 gives the condition). Every marker on a line is its own annotation, and JS and C# catch findings carry the columns of their catch and try, so an annotation no longer exempts every catch on its line: with two tries on one line, a comment above covers only the first try's catches; an annotation inside the first catch no longer exempts a later one; and a one-line nested try annotated after the outer try block's closing brace exempts the outer catch and flags the inner. In C#, a comment after a catch on its line also covers it across later catches of the same try, so a comment above `try { A(); } catch (IOException) { } catch (Exception) { }`, after it or inside its last catch exempts both catches. A comment the columns give to no catch exempts none: `try { /* chemx-allow: best-effort x */ try { a(); } catch {} } catch {}` flags both catches, where main flagged neither. The column is part of the duplicate key, so a console-only catch that shares a line with an empty catch keeps its own finding. Findings without a column (PHP, other rules) keep the line window (#257).
- A `chemx-allow` block comment whose marker line already has the reason lasts to its closer, so `/* chemx-allow: best-effort x` closed by ` */` on the next line, or a JSDoc-style block above a one-line try, covers the catch below it. A block that trails code still does not count (#257).
- The `AI_SLOP_SHALLOW_CATCH` directive names `chemx-allow: best-effort <reason>` (#257).
- Ownership by column can raise both catch-family counts, so they moved to a new rule set: `ERROR_SWALLOWED_EXCEPTION` is at revision 12, and `AI_SLOP_SHALLOW_CATCH` at 13 with #259. `RULESET_VERSION` is 13. A ratchet baseline recorded under an older revision adopts their current counts on the next audit instead of reporting a regression, and the kit's `chemx-ratchet.json` moved to ruleset 13 (#257, #253).
